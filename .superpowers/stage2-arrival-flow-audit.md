## Recommended integration

Its current Stage1 → Stage2 and `CanCommitExitTravel()` guards already constrain it to a qualifying portal presentation. Preserve `FromTutorial` in `CompleteStageInternal()` at line 477. The placed Stage 2 director may test the newly loaded GameMode's options with `UGameplayStatics::HasOption` and a per-world one-shot guard. `FinishTravel()` uses absolute travel, so same-map restart/Continue calls with empty options do not inherit the marker. If a Blueprint node for reading the options is unavailable in this build, expose a small native query. If the implementation uses a session flag instead of URL options, attach it to the accepted travel token, publish it for the matching destination when `ResolveRestartIntent()` runs, and give the Stage 2 director a one-shot world-local consume. `Arrive()` clears transient token state and should continue doing so. `bStageTitlePending`, `bContinueArrival`, and `IsTrackingWorld()` have different semantics and are poor admission criteria.

Place a dedicated director and non-autoplay LevelSequence actor in canonical Stage 2. Gate playback on the arrival marker, local pawn/controller, and resolved gameplay view. If initial possession is pending, retry only while the intended arrival still owns the start and fall back to ordinary gameplay on failure. The current game uses a `BP_QuarterViewCamera` actor. `IsGameplayCameraOwner()` also recognizes the pawn and actors tagged `CatrunGameplayCamera`. The Stage 2 gameplay profile scales ortho width/spring arm by 1.30. It applies in `CatrunLevelFlow.cpp:341` when the player owns the normal view and inputs are unlocked. Preserve that handoff and verify against the existing framing.

- `Source/Catrun/LevelFlow/CatrunExitTransitionComponent.cpp:279` is the cleanup reference.
