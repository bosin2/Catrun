# Catrun — 다른 AI에게 전달할 작업 지침서

작성 기준: 2026-11-25 KST. 이 문서는 프로젝트를 이어받기 위한 지침이다. 이번 요청으로 수행한 일은 문서 작성이며, 게임 수정·에디터 실행·배포는 수행하지 않았다.

## 1. 역할과 목표

너는 Unreal Engine 프로젝트 Catrun의 후속 작업 담당 AI다. 기존 결과물과 사용자의 최신 요구를 먼저 이해하고, 사용자가 지정한 작업을 완료한다. 이미 만들어진 것을 처음부터 재제작하거나, 아래의 미완료 목록 전체를 자동으로 실행하지 않는다. 재개할 작업이 지정되지 않았다면 문서를 읽고 현재 상태를 요약한 뒤 작업 범위를 확인한다.

게임은 《마왕님, 고양이가 도망갑니다》이며, 고정 각도 쿼터뷰 잠입·유인·환경 퍼즐 게임이다. 핵심은 고양이가 자기 위치에서 방울로 갑옷을 유인하고, 열린 경로와 캣홀을 이용해 우회하는 것이다.

## 3. 반드시 읽을 문서와 우선순위

경로는 별도 표시가 없으면 선택한 프로젝트 루트 기준이다.

1. `AGENTS.md`: 프로젝트 작업 지침. 오디오 전용 규칙을 일반 작업 전체에 확대하지 않는다.
2. `Docs/Design/GameDesign_Source.md`: 사용자 원본 기획 의도.
3. `Docs/Design/GameDesign.md`: 현행 통합 기획과 최신 정정.
4. `Docs/Design/GameplayExpansion_Request_2026-11-24.md`: 스태미나·시간·저장 정책 및 Stage2 저장 롤백 정정.
5. `Docs/Reviews/TeamAgenda_2026-11-25.md`: 미정 사항. AI가 임의로 확정하지 않는다.
6. 아래 작업별 상세 인계서, 해당 리뷰와 실행 증거.
7. `HANDOFF.md`: 누적 이력. 오래된 ‘최신’, ‘미완료’, ‘푸시 안 함’ 문구를 현재 사실로 그대로 옮기지 않는다.

현재 사용자의 명시적 지시와 해당 작업의 최신 정정이 오래된 계획보다 우선한다. 문서와 코드가 다르면 요구사항·구현 상태·검증 결과를 구분해서 설명한다. 문서에 기록된 과거 승인이나 완료 수치는 새 작업 전체의 승인이나 최신 바이너리 검증으로 확대하지 않는다.

## 4. 유지해야 할 게임 규칙과 원본

- Stage2는 도달 챕터·해금만 보존한다. 이어하기·포획·시간 초과·수동 재시작은 일반 시작점, 초기 퍼즐, 전체 Stage2 제한 시간으로 돌아간다. 취소된 중간 저장과 Gate11 앞 재시작을 되살리지 않는다. Stage1 시간 저장은 유지한다.
- 소리는 열린 연결과 바닥 감쇠를 따라 전달된다. 벽을 뚫는 단순 거리 판정으로 바꾸지 않는다. 갑옷이 소리를 듣고, 촛불은 청각 유인 대상이 아니다.
- 캣홀의 방울 금지는 최신 규칙이다. 원본 기획의 허용 문장을 근거로 복구하지 않는다.
- 고양이의 기존 외형·얼굴·비율·메시·스켈레톤/리그를 보존한다. SourceArt의 실험 리그나 프리뷰가 최종 승인본이라고 가정하지 않는다.
- 튜토리얼의 원래 안내·인트로·계단 연출, 기존 맵·Blueprint·재질·시네마틱·설정·사용자 저장을 보존한다.
- Stage3의 반대편 카메라 구도는 Stage3 전용 요구다. Stage1·2 공유 카메라를 함께 뒤집거나 맵 전체를 다시 반전하지 않는다.
- 수치 조정, 구조 변경, 새 엔딩 등 미정 기획은 발견한 문제와 제안을 제시한 뒤 사용자 결정에 따른다.

## 6. 작업 시작 순서

1. 사용자가 맡긴 작업과 최신 중단·검증 지시를 확인한다.
2. 대상 경로에서 `git status --short`, `git rev-parse HEAD`, `git worktree list`를 확인한다. 다른 사람/AI의 변경을 분리해 보존한다.
3. 관련 상세 인계와 실제 소스·에셋·보고서를 읽는다. Saved 증거가 현재 worktree에 없으면 본 프로젝트 위치를 확인한다. 없는 증거를 검사 성공으로 취급하지 않는다.
4. Unreal 작업이면 연결된 MCP의 프로젝트·현재 레벨·PIE 여부부터 확인한다. 도구 목록이나 포트 응답만으로 연결·작동 성공을 선언하지 않는다.
5. 오래 열린 사용자 에디터의 맵을 그대로 저장해 최신 디스크 파일을 덮어쓰지 않는다. 동시 작업 중 동일 맵/에셋의 저장은 한 담당자가 순서대로 처리한다.
6. 요청 범위의 최소 변경을 적용하고 관련 검사만 수행한다. 사용자 검증으로 넘긴 항목을 임의로 다시 확대 실행하지 않는다.
7. 변경 파일, 실제 검증 결과, 미검증 항목, 증거 경로를 짧게 보고하고 해당 인계 문서를 갱신한다.

## 7. 효과적이었던 방식과 피해야 할 실패

- 별도 검증 프로젝트, 격리 저장 파일, 적용 전 dry-run으로 사용자 작업을 보존한다. 다만 별도 환경 성공과 본 프로젝트 적용 완료는 구분한다.
- 빌드 성공, BP 컴파일, 맵 저장·재로드, 실제 PIE 행동을 각각 구분한다. 자동화 성공 개수에는 실패·스킵·경고와 fixture 사용 여부를 함께 기록한다.
- Stage3 카메라 검사는 지원하지 않는 `CameraActor.get_camera_component()` 때문에 실패한 기록이 있다. 수정된 `get_component_by_class(unreal.CameraComponent)` 경로를 확인하고, 이를 게임 타이밍 결함으로 오인하지 않는다.
- 과거 빌드 도중 동시 소스 변경으로 오브젝트가 섞여 링크 실패한 기록이 있다. 소스 버전을 안정시킨 뒤 재빌드하고 다른 작업을 되돌려 해결하지 않는다.
- 에디터가 DLL을 사용 중이면 최종 링크가 실패할 수 있다. 사용자 에디터를 임의 종료하지 말고 현재 적용/재시작 조건을 확인한다.
- `git reset --hard`, `git clean`, 전체 파일 덮어쓰기, 무차별 스테이징으로 다른 작업을 정리하지 않는다. 이번 문서 요청은 커밋·푸시 지시가 아니다.
- 사용자가 ‘멈춰’, ‘검증은 내가 할게’, ‘캡처하지 마’라고 하면 해당 작업을 중단한다. 필요한 상태와 남은 항목만 인계한다.
- 스크린샷과 미리보기는 요청된 납품 계약에 맞춘다. 사용자 아트 승인과 기술 QA 통과를 혼동하지 않는다.

## 8. 오디오를 요청받았을 때만 적용

`AGENTS.md`와 `.agents/skills/cat-audio-director/SKILL.md`를 읽고 단일 디렉터로 진행한다. 독립 BGM/SFX를 병렬 하위 에이전트에 맡기고, 결과 수집 → 편집 → Unreal 통합 → QA 순으로 처리한다.

새 코드는 `Scripts/CatAudioDirector`, 실행 산출물은 `Saved/CatAudioDirector`, 임포트는 `/Game/Audio/CatAudioDirector` 아래 새 실행별 폴더를 사용한다. 기존 에셋을 암묵적으로 교체하지 않는다. 들리는 음원 추가로 게임플레이 소리 전파·적 인지 규칙을 바꾸지 않는다.

공급자 라이브 도구와 스키마를 먼저 확인한다. Suno 로그인은 유료 생성 승인이 아니다. 구체적인 생성 묶음과 크레딧 상한의 명시적 승인을 받은 후 결제성 생성을 실행한다. 기능이 확인되지 않으면 mock/local 결과와 실제 음원 생성·재생 여부를 구분한다. Blender는 오디오 작업의 필수 조건이 아니다.

## 9. 새 AI에 복사해 전달할 시작 프롬프트

> Catrun 프로젝트를 인계받아라. 먼저 이 지침서와 AGENTS.md, 현행 기획, 작업별 상세 인계서를 읽어라. 현재 작업 폴더와 실제 Unreal 프로젝트 C:\Users\whghk\Catrun의 관계, Git 변경, 적용 상태를 확인하라. 과거 검사 결과를 현재 실행 검증으로 주장하지 마라. 기존 고양이 외형·리그·게임 규칙과 다른 작업자의 변경을 보존하라. 내가 지정한 작업부터 이어서 완료하고, 완료한 변경·실제로 검증한 항목·남은 항목을 짧게 보고하라. 아직 재개할 작업을 지정하지 않았다면 먼저 인계 내용을 요약하고 작업 범위를 확인하라.
