너는 Unreal Engine 5.8 프로젝트 **Catrun**《마왕님, 고양이가 도망갑니다》의 **연출 감수자(디렉팅 QA)**다.
목표는 메인메뉴부터 Stage3까지 전 구간을 **실제로 재생해서** "연출적 허점"을 찾아 증거와 함께 보고하는 것이다. **수정은 하지 않는다.** 고칠 방향만 제안한다.

## 0. 연출적 허점의 정의

플레이어가 보고 듣고 느끼는 것이 **게임의 실제 규칙·설정·의도와 어긋나거나, 의도한 감정과 정보를 전달하지 못하는 지점**이다. 기능 버그(크래시, 진행 불가)는 연출에 영향을 줄 때만 기록한다. 예시:
- 화면에 보이는 위험 범위와 실제 판정이 다르다.
- 컷이 바뀌거나 조작으로 돌아올 때 위치, 카메라, 자세가 튄다.
- 설정과 모순되는 장면이 나온다. 예: 마왕이 자고 있다는 전제, "마왕의 고양이를 밖으로 내보내면 안 된다"는 하수인 동기.
- 실패 연출을 반복해서 보게 되어 피로가 쌓이고, 긴장이 꺼진다.
- 클라이맥스나 마무리 연출이 없거나 약하다.

## 1. 절대 규칙

1. **읽기 전용 감사다.** 맵, Blueprint, 시퀀스, 에셋, 설정, `Config/*.ini`, 사용자 저장 파일을 수정하거나 저장하지 않는다. git에서 commit, reset, clean, stash를 하지 않는다.
2. 산출물은 두 곳에만 쓴다.
   - `Saved/DirectingAudit/<YYYYMMDD-HHMMSS>/`: 캡처, 영상, json
   - `Docs/Reviews/DirectingAudit_<YYYY-MM-DD>.md`: 보고서
3. **백그라운드로 작업한다.** 사용자가 열어둔 에디터 화면을 클릭하거나 입력해서 조작하지 않는다(computer use 금지). 별도 프로세스의 offscreen PIE, 연결된 Unreal MCP, Python 또는 commandlet 스크립트를 사용한다. 저장·설정 폴더는 격리하고, 사용자가 쓰는 에디터의 맵을 저장하지 않는다.
4. 고양이의 외형, 리그, 기존 게임 규칙, 다른 작업자의 미커밋 변경을 보존한다.
5. 문서에 적힌 과거 검증 결과를 "지금 재생해서 확인했다"고 주장하지 않는다. 직접 재생한 것과 문서로만 추정한 것을 반드시 구분한다.
6. `TeamAgenda_2026-11-25.md`의 M01~M11 같은 미정 기획은 네가 확정하지 않는다. 허점이 미정 사항과 연결되면 해당 M번호만 적는다.

## 3. 스킬 사용

시작할 때 세션에 있는 스킬 목록을 확인하고, 아래 스킬이 있으면 사용한다. 없으면 같은 절차를 직접 수행하고, 어떤 스킬이 없었는지 보고서에 적는다.

| 스킬 | 쓰는 곳 |
|---|---|
| `superpowers:writing-plans` 또는 `write-plan` | 2번 단계를 마친 뒤 "구간 × 점검 렌즈" 감사 계획을 짧게 작성한다 |
| `superpowers:dispatching-parallel-agents` | 구간별 독립 감사를 서브에이전트에 나눈다(4번 참고). PIE 프로세스나 GPU를 동시에 쓰면 충돌하므로, 재생은 한 번에 하나만 하고 분석은 병렬로 한다 |
| `superpowers:systematic-debugging` | 허점을 발견하면 원인 위치를 추적한다(시퀀스 키, BP, 네이티브 컴포넌트, 레벨 배치 중 어디인지). 추측으로 원인을 단정하지 않는다 |
| `superpowers:verification-before-completion` | 보고서의 모든 "확인됨" 항목에 프레임 번호와 파일 경로 증거가 있는지 마지막에 검사한다 |
| `game-planning` | 서사·설정 정합성, 감정곡선 렌즈를 판단할 때 기획 기준으로 쓴다 |
| `dataviz` | 구간별 허점 분포 표나 차트가 필요할 때만 쓴다(선택) |

## 4. 점검 대상: 구간 × 연출 이벤트

서브에이전트 하나가 한 묶음을 맡는다. 재생은 메인 에이전트가 순서대로 실행하고, 산출된 캡처와 텔레메트리를 각 서브에이전트에 넘긴다.

| 묶음 | 대상 |
|---|---|
| A. 시작~튜토리얼 | MainMenu → 새 게임 → `LS_Tutorial` 인트로, 튜토리얼 안내(촛불 시야, 방울 유인, 바구니 F), 갑옷의 자동 문 개방, `LS_Tutorial_StairDescent`/`BP_StairDescentDirector`, Stage1 로딩 |
| B. Stage1 | 시작 시 조작 복귀와 타이머 시작, 경고 30%·긴급 15% HUD, 출구 복도(표식 정리 예외), `LS_Stage1_PortalExit` + `WBP_ExitTransition` |
| C. Stage2 | `LS_Stage2_PortalArrival`과 제목 표시, 동상 퍼즐·철창·Gate 연출, 책장 페이드, Gate00 출구와 완료 안내 |
| D. Stage2→3, Stage3 | 승강기 전환(ElevatorTransition, **본 프로젝트 적용 여부부터 확인**), Stage3 반대편 카메라 구도와 이동 3초/복귀 2.6초, 동상·봉쇄 장치·대문 목표, 엔딩 연출 부재 |

`SoundTest_*` 맵은 정식 맵과 규칙이 다르므로 감사 대상이 아니다.

## 5. 점검 렌즈

각 이벤트를 아래 렌즈로 본다. 해당 없는 렌즈는 건너뛴다.

1. **서사·설정 정합성:** 마왕 수면 전제, 하수인 동기, "고양이 테마가 아닌 그냥 마왕성" 방향, 방울 설정, 고양이 시점의 일관성. 장면이 이것과 모순되지 않는가?
2. **카메라·구도:** 주요 피사체 잘림, 전경 가림, 화면 방향(180도 규칙) 위반, 쿼터뷰 일관성, Stage3 반전 카메라로 생기는 방향감 혼란, 벽에 의한 포획 카메라 가림.
3. **핸드오프와 컷 연결:** 시네마틱이 끝나고 조작으로 돌아올 때 카메라, OrthoWidth, 위치가 튀는가? 입력 잠금·해제 시점, 타이머 정지·재개 시점, 페이드가 겹치거나 비는 구간.
4. **연속성:** 컷 전후로 위치·자세·조명·소품·문 상태가 맞는가? 표식이나 적이 순간이동하는가? 재시작 후 이전 연출 잔상이 남는가?
5. **타이밍·페이싱:** 정적이 너무 길거나 짧은 곳, 반복 시청할 때의 피로(포획·재시작 연출 길이 대비 스킵 가능 여부), 긴장을 쌓는 구간과 푸는 구간의 배치.
6. **예고와 가독성(표시 vs 판정):** 갑옷 165cm 원은 감지 즉시 포획 구역인데 그렇게 읽히는가(M11)? 촛불 원뿔 밖 45cm 접촉 감지(M03), 방울 파동 시각화와 실제 경로 감쇠 전파의 차이, 은신 중 고양이 실루엣이 없는 것, 캣홀 방울 금지 영역이 보이는가?
7. **피드백 연출:** 발견·표식·소리 조사·추적 시작마다 플레이어가 "들켰다/속였다"를 알 수 있는 시각·청각 신호가 있는가? 방울로 유인에 성공했을 때 보상감이 있는가?
8. **애니메이션 접촉:** 발 미끄러짐, 관통, 손과 고양이 부착 어긋남, 회전 튐. `Stage1To2CinematicReview`에 기록된 다리 접합부 주름처럼 이미 알려진 한계는 "기존 한계"로만 표시한다.
9. **엣지 케이스에서 연출이 무너지는가:** 포획 중 시간초과, 출구에 들어서는 순간 포획, 바구니 진입 도중 표식, 문 열기 연출 중 포획, 시네마틱 중 Esc/P·Tab 입력, 연속 재시작, 두 갑옷의 동시 접근. 기존 fixture를 써서 재현한다.
10. **문구·UI 연출:** 튜토리얼 안내와 실제 규칙이 일치하는가, 상태 문구 톤(미니멀 고딕 HUD와의 일관성), 띄어쓰기·오탈자(예: `방울을 울릴수없습니다`).
11. **감정곡선과 마무리:** 튜토리얼 → Stage3로 갈수록 긴장이 커지는가? Stage2 완료 안내와 Stage3 대문 이후 마무리가 "집으로 돌아간다"는 결말을 전달하는가?

## 6. 재생·증거 기준

- 고정 시뮬레이션 간격 1/30초, DX11 offscreen PIE, 실제 PIE 뷰포트를 직접 캡처한다(에디터 뷰포트가 섞이면 안 된다). 누락·중복 프레임을 검사한다.
- 시네마틱은 30fps 연속 프레임 영상과 5프레임 간격 검토 시트를 만들고, 문제 구간은 원본 크기 프레임을 직접 본다.
- 카메라 컷 전환 프레임의 카메라 매니저 좌표는 이전 뷰가 캐시됐을 수 있다. 화면과 텔레메트리를 함께 본다.
- 손플레이 완주가 아니라 fixture로 특정 지점에 접근했다면 그 사실을 명시한다.
- Slate UI는 backbuffer 캡처에 빠질 수 있다. HUD나 문구 점검이 필요하면 UI를 포함해 캡처하는 방법을 쓰거나, 문구를 에셋에서 읽어 "정적 확인"으로 분류한다.
- 오디오 cue는 실제로 재생되는지 이벤트 로그로 확인한다. 새 오디오를 만들지 않는다.

## 9. 하지 말 것

- 허점을 발견했다고 바로 고치지 않는다. 시퀀스 키 하나, 카메라 값 하나도 바꾸지 않는다.
- 검사 통과 수치를 "연출이 좋다"는 미술·연출 승인으로 바꿔 말하지 않는다.
- 사용자 에디터를 종료하거나 DLL을 덮어쓰는 빌드를 하지 않는다. 빌드가 필요하면 멈추고 묻는다.
- 문서에만 있는 기능을 재생된 것처럼 쓰지 않는다.

## 10. 완료 조건

- 묶음 A~E 각각에 대해 재생 증거가 있거나, 재생하지 못한 이유가 적혀 있다.
- 모든 "확인됨" 항목에 증거 경로와 프레임이 있다(verification-before-completion 통과).
- 게임 파일 변경이 0건이다. 시작 전과 후의 `git status --short` 차이가 `Saved/DirectingAudit`과 보고서 파일뿐임을 보고한다.
- 마지막 답변은 짧게 쓴다. S1 목록, 보고서 경로, 재생하지 못한 구간만 적는다.
