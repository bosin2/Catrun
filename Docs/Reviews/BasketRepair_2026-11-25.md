# 바구니 조작·재질·첫 방 통로 수정

## 최종 적용 기준

- 평소 보행과 동일한 카메라 전방/우측 수평 벡터로 WASD 탈출 방향을 계산한다. 대각선 조합과 키 재설정도 따르며, 바구니 회전에 스냅하지 않는다.
- A/D 순환과 전체 출구 목록을 제거했다. 입력 전에는 출구를 자동 선택하지 않으며, 키를 놓으면 마지막으로 직접 선택한 방향을 유지한다. 막힌 방향도 자동으로 다른 곳으로 바꾸지 않는다.
- 기존 점선 경로와 착지 원 하나만 표시한다. 지지 바닥은 있지만 경로가 막혔으면 같은 위치를 붉게 표시하고 F 확정을 거부한다. 반투명 벽에 가려지지 않도록 안내 재질의 깊이 검사를 끄고 표시 우선순위를 1000으로 지정했다.
- 진입은 실제 접근 방향을 유지한다. 천의 기존 8방향 클립은 실제 진입/탈출 벡터에 가장 가까운 클립을 선택하며, 천 방향이 고양이 이동 방향을 결정하지 않는다.
- 충돌 검사는 사용 중인 바구니의 선택 방향 하나에서 0.2초 간격으로 실행한다. 방향 변경/F 확정/착지 시 다시 검사한다. 바닥 지지, 실제 캡슐 경로, 복원할 충돌 프로필과 늦게 생긴 장애물에 대한 안전 복귀를 유지했다. 대기 중인 천에는 상시 애니메이션 Tick을 추가하지 않았다.
- 천 체크무늬는 세 SkeletalMesh 슬롯이 WorldGridMaterial을 참조한 문제였다. M_Cloth_Stage1/2/3을 연결하고 스켈레탈 메시 사용 플래그를 저장했다. 임포트 스크립트도 구조체 배열 원소를 인덱스로 다시 대입하도록 수정했다.
- Stage1 창고 바구니가 입구의 보행 통로를 막았다. 본체·천·상호작용 액터를 X=710에서 X=760으로 함께 50cm 이동했다. Y=1750, 높이와 회전은 유지했다. Stage1과 SoundTest_Stage1에 저장했고 다른 액터의 위치·회전·크기는 바뀌지 않았음을 비교했다.

## 검증

- 작업 완료 후 일반 에디터를 `/Game/Maps/Tutorial`로 다시 열고 새 프로세스에서 실제 맵 경로와 세 천 재질 연결을 확인했다: `Saved/BasketRepair20261125/editor_reopened.json`.

- 최종 빌드 성공: `Saved/BasketRepair20261125/build_wasd_final.log`.
- 자동 회귀 검사 13/13 통과: `Saved/BasketRepair20261125/AutomationWasdFinal/index.json`. 비정렬 카메라 각도, 회전한 바구니, WASD/대각선, 키 재설정, 단일 안내, 선택 방향 유지, 충돌/지지/안전 복귀를 포함한다.
- 실제 Stage1/2의 바구니 5개 × WASD/대각선 8종, 총 40개 입력 시나리오 통과: `Saved/BasketRepair20261125/WasdFinal/report.json`.
- 탈출 후 실제 BP 보행 입력 벡터와 탈출 벡터 일치 40건, 서로 다른 착지점 34곳. 막힌 입력에서 F가 거부되고 선택이 유지된 사례 6건은 검사 스크립트가 명시적으로 다른 키를 입력한 뒤 탈출했다. 게임이 자동으로 대체 출구를 선택한 결과가 아니다.
- 실행 중 Stage2 Room4의 SD 탈출에서 Armor_02가 착지점과 이동 경로를 점유해 늦은 안전 복귀 1회가 기록됐다. 같은 방향을 다시 명시적으로 입력해 탈출을 완료했다. 자동 대체 출구 이동은 없었다. 복귀 순간 물리 검사 기록은 해당 사례의 `late_returns`에 보존했다.
- 첫 창고 바구니는 8개 입력 시나리오 모두 탈출 후 실제 WASD로 복도 X<600까지 걸어 나갔다. 착지와 방 밖 이동에 위치 강제 변경을 쓰지 않았다.
- 모든 사례에서 실제 진입/탈출 방향에 맞는 천 클립 이름과 고양이/천 재생 시간차 0.12초 이내를 검사했다. 안내 메시 인스턴스는 기존 점선 16개 + 원 32개, 한 경로 48개로 제한됐다.
- 세 스테이지 천 재질 슬롯과 스켈레탈 사용 설정을 새 프로세스에서 재확인했다.
- 최종 화면: `WasdFinal/Stage1_BP_S1_storage_HideBasket_26_Interaction_selection.png`, `WasdFinal/Stage2_S2_Basket_Room2_selection.png`, `WasdFinal/storage_walked_out.png`. 이전 A/D 순환 결과와 다중 출구 화면은 최종 증거에서 제외한다.
- 검증 스크립트의 키 해제/재입력을 서로 다른 프레임으로 분리한 뒤 연속 재진입 후 보행 검사가 통과했다. 초기 검사 실패 기록은 `Diagnostics/wasd_walk_sample_first.json`, `Diagnostics/wasd_walk_sample_second.json`에 보존했다.
- 검사 중 Stage2 화면에 VRAM 예산 초과 경고가 관측됐다. 이 검사는 조작·충돌·애니메이션 검증이며 프레임 성능 측정이 아니다.

DX12 격리 PIE에서 실제 키 입력을 사용한다. 바구니 근처 시작 위치는 테스트용으로 배치하며, 포획만 해당 테스트 프로세스에서 끄고 적의 이동과 충돌은 유지한다. 탈출 후 실제 보행 입력 벡터와 선택한 탈출 벡터를 비교한다. Stage1 첫 방은 탈출 후 실제 WASD로 복도까지 걸어 나가는 과정을 별도로 기록한다. 전체 캠페인 수동 완주나 Stage3 게임플레이 검증을 뜻하지 않는다.
