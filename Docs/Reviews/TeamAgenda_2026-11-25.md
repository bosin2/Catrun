# Catrun 팀회의 안건 — 2026-11-25

최신 사용자 정정: Stage2 중간 저장을 취소하고 챕터 해금 저장으로 되돌린다. 따라서 아래의 `완료 퍼즐 저장` 확정 문구와 M02의 누적 완료 전제는 폐기되었다. Stage2는 이어하기·실패·수동 재시작마다 초기 퍼즐과 전체 시간을 사용하며 일반 시작점에서 시작한다. M08의 시간 저장 논의는 Stage1에만 적용한다. 이 문서의 나머지 제안과 원래 감사 내용은 보존한다.

목적: 구현 상태를 공유하고, 서로 충돌하는 규칙·남은 제작 범위를 결정한다. 아래 선택지는 제안이며 이 문서 작성으로 채택되지 않는다. 확정 요구를 조용히 되돌리거나 미구현 기능을 완료로 표시하지 않는다.

참조: [전체 기획서](../Design/GameDesign.md), [점검 보고서](ProjectAudit_2026-11-25.md).

## 먼저 구분할 것

- **이미 최신 요구로 확정:** 달리기134, 스태미나, Stage1/2 제한시간, 완료 퍼즐 저장, 실패 후 일반 시작점·시간 재충전, 캣홀 방울 금지, 최근접 갑옷1기 표식 호출. 예전 원문과 다르다는 이유로 다시 미정 처리하지 않는다.
- **수치가 임시:** 600/900초, 스태미나 재달리기20, 경고30%·15%. 경로 측정·플레이 피드백 필요.
- **사용자에게 판단을 받아야 하는 것:** 아래 M01~M11. 기술팀의 테스트 보완·기획서 최신화는 회의 의결을 기다릴 이유가 없다.

## M01. 고양이 달리기보다 빠른 갑옷 순찰 — 우선

**사실:** BP의 고양이53/79/134, 실제 배치 갑옷 WalkSpeed150. 원래 문서는 걷기 < 갑옷 순찰 < 고양이 달리기였다. 최신 요구는 고양이만124→134, 적 속도는 유지다.

**결정 질문:** 순찰 중인 갑옷도 고양이보다 빠른 관계를 정식 밸런스로 유지할 것인가?

- 안 A: 현행 유지. 같은 방향으로 달려 제치는 경로보다 유인·옆길을 요구한다.
- 안 B: 순찰 속도만 조정. 사용자 승인 후 레벨 타이밍·애니메이션·문 통과를 함께 재검증한다.

**필요 증거:** 새 스태미나에서 튜토리얼·Stage1·Stage2 대표 순찰 교차 경로의 성공/실패 시간. **담당 제안:** 기획+AI/레벨. **기록할 결정:** 채택 관계, 적용 구간, 수치 조정 책임자.

## M02. 실패 반복과 영구 퍼즐 완료의 관계 — 우선

**사실:** 최신 요구는 A/B/C 완료 유지, 포획/시간초과 때600/900초 재충전이다. 완료 하나를 저장하고 일부러 잡힌 뒤 다음 퍼즐을 푸는 전략이 가능하다. 코드 버그라고 단정할 수 없는 요구사항의 결과다.

**결정 질문:** 제한시간은 한 번의 완주를 요구하는가, 여러 시도에 걸친 누적 해결을 허용하는가?

- 안 A: 누적 해결을 의도된 접근성 규칙으로 유지하고 UI/안내에서 명시한다.
- 안 B: 한 시도 완주를 목표로 바꾸되, 기존 저장·실패 요구를 변경하는 별도 승인과 설계가 필요하다.

**필요 증거:** 첫 시도/누적 해결 시도별 총 소요시간과 체감 긴장. 새 패널티를 이번 감사에서 추가하지 않는다. **담당 제안:** 기획+레벨.

## M03. 촛불 원뿔 밖 접촉 감지와 위험 표시 — 우선

**사실:** `CheckForCat`은 `TouchRadius45cm OR CanSee`를 사용한다. 벽 차폐는 적용하지만 원뿔 뒤·옆의 근접 고양이도 발견할 수 있다. 바닥 표시 생성은 원뿔 중심이며 독립적인45cm 접촉 원 표시 경로는 확인되지 않았다.

**결정 질문:** 촛불과 몸이 가까워지면 원뿔 밖에서도 들키는 규칙을 유지할 것인가?

- 안 A: 유지하고 접촉 위험을 명확히 표시·튜토리얼에 안내한다.
- 안 B: 시야 판정만 유지한다. 촛불 몸체 충돌과 뒤쪽 통과 플레이를 함께 검증한다.

**필요 증거:** 실제 접촉 가능한 뒤/옆 위치에서 바닥 표시와 표식 발생 비교. **담당 제안:** 기획+UI+AI. 원문 “표시와 판정 일치”의 예외를 암묵적으로 두지 않는다.

## M04. 튜토리얼 방울 범위가 본편보다 넓은 이유

**사실:** 실제 저장 맵에서 Tutorial 플레이어 방울 예산650, Stage1/2 공유500. 벽을 뚫는 반지름이 아니라 감쇠 경로 예산이다.

**결정 질문:** 튜토리얼 전용650을 유지하고 차이를 알려줄 것인가, 학습을 일관되게 맞출 것인가?

**선택지:** 현행+설명 / 본편과 범위 통일 후 튜토리얼 배치 재검증. 범위만 줄이면 기존 문·캣홀 유인이 깨질 수 있다. **담당 제안:** 기획+레벨+튜토리얼.

## M05. 움직이는 갑옷이 소리를 듣는 시점

**사실:** 발음 시점 위치로 청취 대상을 고르고 도착 시각을 예약한다. 예약 실행에서는 갑옷의 현재 위치·새 차폐 상태를 다시 판정하지 않는다.

**결정 질문:** 소리는 발음 순간의 결과를 지연 전달하는가, 이동하는 파동과 갑옷이 실제로 만날 때 듣는가?

**선택지:** 현재 스냅샷 규칙을 공식화 / 도착 시 재검증 또는 이동 파동 수신으로 변경. 후자는 추가 전파 계산·문 상태·파동 시각과의 동기화가 필요하다. **담당 제안:** 시스템+기획. 현행을 물리적 파동 접촉이라고 설명하지 않는다.

## M06. 바구니·캣홀의 안전 및 체류 규칙

**사실:** 바구니는 진입 단계부터 안전 판정, 은신 후 메시 숨김. 전용 실루엣·적 수색은 없다. 캣홀은 금지 영역에서 방울을 못 쓰지만 체류 강제 종료는 확인되지 않았다. 본편에서 기다리는 동안 제한시간은 흐른다.

**결정 질문:** 실루엣을 실제로 만들 것인지, 진입 즉시 안전을 유지할지, 캣홀 체류·왕복을 시간 비용만으로 허용할지 결정한다.

**추천 검토 순서:** 현행 시간 비용으로 플레이 측정 → 이해가 어려우면 표시 보완 → 필요할 때만 수색/체류 제한 검토. 새 바구니 외형 제작과 안전 규칙 변경을 한 작업으로 섞지 않는다. **담당 제안:** 기획+캐릭터/상호작용.

## M07. Stage2 B 퍼즐은 필수인가 — 우선

**사실:** 출구 완료 코드에 A/B/C 전체 완료 마스크 요구가 없다. 11월16일 기록에는 B를 생략한 탈출이 있으며, 이는 과거 경로 증거이지 11월25일 새 완주 증거는 아니다. 세 링크가 존재하는 것과 세 링크가 필수인 것은 다르다.

**결정 질문:** B는 선택 우회로/안전 동선인가, 반드시 풀어야 하는 목표인가?

- 선택이면 UI 목표·저장·완료 안내를 그에 맞게 정리한다.
- 필수이면 공간 연결 또는 출구 조건을 명시하고 안내를 추가한다. 이번 감사에서 임의로 출구를 잠그지 않는다.

**필요 증거:** 최신 맵에서 A/B/C별 통행 변화와 B 생략 경로 실측. **담당 제안:** 기획+레벨.

## M08. 시간 저장의 허용 손실과 재시작 UX

**사실:** 퍼즐 완료·전환·메뉴·정상 종료 저장 경로는 있으나 일정 주기의 시간 저장은 없다. 강제 종료 시 마지막 저장 뒤 소모한 시간이 복구될 수 있다. 정상 종료 시 최종 진행을 놓치지 않는 것과 비정상 종료를 견디는 것은 별개다.

**결정 질문:** 최대 몇 초/분의 시간 롤백을 허용할 것인가? 새 게임·챕터 선택·현재 구간 리셋 안내가 각각 무엇을 보존하는지 어디에 보여줄 것인가?

**선택지:** 현재 이벤트 저장만 허용 / 일정 간격의 조용한 시간 저장. 후자는 쓰기 빈도·실패 재시도·저장 안내 남발을 검토한다. **담당 제안:** 시스템+UI+기획.

## M09. Stage3 목표 장치와 최종 탈출 — 제작 범위 확정

**사실:** 현재 실행 경로·패키징 맵은 Stage2까지다. Stage3 환경 아트 제작은 진행 중이지만 플레이 맵·목표·클리어·엔딩은 확인되지 않았다. 구형 자동 방울 성문 발판은 보관 후보다.

**결정할 산출물:** 목표 한 문장, 필수 유인 상황, 동선, 실패/저장 정책, 필요한 오브젝트와 적, 완료 후 화면/엔딩, 제작 담당·기한. 이 목록 없이 장치 후보를 확정 구현으로 취급하지 않는다.

**담당 제안:** 기획+레벨+아트+시스템. 최대3기 표식 확대·가구 밑·수집물은 필요성을 먼저 판단하고 자동으로 범위에 넣지 않는다.

## M10. 정식 맵·테스트 맵 유지 정책

**사실:** 정식 Tutorial/Stage2에는 NoBellZone이 각각1/2개, 대응 SoundTest 맵에는0/0개다. Stage1은 양쪽2개다. 배치와 규칙이 이미 다르다.

**결정 질문:** 테스트 맵을 계속 동기화할 것인가, 차이를 명시한 실험 맵으로 유지할 것인가?

**추천:** 출시 수용 검사는 정식 맵 고정. 테스트 맵은 목적·차이·소유자를 기록한다. 자동 동기화 도입 여부는 별도 결정. **담당 제안:** 레벨+QA.

## M11. 갑옷 감지 즉시 포획인가, 추적 뒤 접촉 포획인가 — 우선

**사실:** 원문은 원형 감지 진입→실시간 위치 추적, 몸이 닿으면 포획이다. 현재 `UpdateDetection`은 감지·차폐·고양이 몸체 경로가 허용되면 `StartCatch`→`BeginCapture`로 바로 이동 잠금과 포획 연출을 시작한다. 별도 접촉 거리 문턱은 없다. 실제 공유150+고양이반경15cm 안이 이 조건의 범위다.

**결정 질문:** 현재 원형 구역을 즉시 포획 위험 구역으로 확정할 것인가, 원문처럼 감지 추적 단계와 더 짧은 포획 범위를 분리할 것인가?

**선택지:** 현행 유지+기획/튜토리얼에 정확히 안내 / 감지·추격·접촉 포획을 분리. 후자는 새 상태 전환, 속도, 포획 연출 접근, 바구니/캣홀 경계, 철창 차단을 함께 재검증해야 한다. 이번 감사에서는 포획 거리를 바꾸지 않는다. **담당 제안:** 기획+AI+캐릭터 연출.

## 회의가 없어도 진행할 기술 작업

1. 최신 DLL·에셋 기준으로 자동화 실패의 원인을 확인하고 초기 실패/최종 재검사를 모두 보존한다.
2. 실제 로컬 플레이어·실제 CharacterMovement를 사용하는 시간/발소리 테스트와 퍼즐 복원 테스트를 보완한다.
3. 새 프로세스 저장 검사를 실행 파일에 포함해 write→read→reset→readreset을 검증한다. 테스트명 미검출·0개 실행을 성공으로 처리하지 않는다.
4. 새 HUD·미니맵·설정 확인창을 정식 맵에서 검증한다. 에셋 생성 실패가 난 중간 결과를 최종 결과로 보지 않는다.
5. 출시 전 패키지 빌드, 화면·음향·프레임 측정, 무적/순간이동 없는 전체 연속 완주를 별도로 수행한다.
