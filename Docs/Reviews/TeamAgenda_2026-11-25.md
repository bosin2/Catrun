# Catrun 팀회의 안건 — 2026-11-25 (최신 정리판)

목적: 현재 구현과 기획이 어긋나는 부분, 남은 제작 범위를 회의에서 결정한다. 아래 선택지는 제안일 뿐이며 이 문서로 채택되지 않는다.
참조: [현행 기획서](../Design/GameDesign.md) · [전체 점검 보고서](ProjectAudit_2026-11-25.md)

## 0. 이미 확정된 것 — 다시 논의하지 않음

- 고양이 이동 53/79/134, 달리기 스태미나
- Stage1/2 제한시간, 실패(포획·시간초과) 시 일반 시작점에서 시간 재충전
- **Stage2는 도달 챕터·해금만 저장.** 이어하기·실패·수동 재시작마다 초기 퍼즐(A/B/C)·전체 제한시간·일반 시작점. 중간 저장/퍼즐 완료 저장은 **취소됨**. Stage1 시간 저장은 유지
- 캣홀 안 방울 금지, 표식은 가장 가까운 갑옷 1기 호출
- Stage2 → Stage3 전환: 출구 안전 복도 → 창고 승강기 → F로 고리 당기기 → 상승 시네마틱 → Stage3 입구 (승강기는 1회용)

**임시 수치(조정 필요):** 제한시간 600/900초, 스태미나 재달리기 20, 경고 30%·15%

| **M02** Stage2 한 번에 완주 난이도 *(재작성)* | 퍼즐 완료 저장이 취소되어 실패할 때마다 A/B/C와 900초가 전부 초기화됨 → 한 시도 안에 전부 풀어야 함 | 900초 한 번의 시도로 완주가 적정한가 | A 900초 유지 / B 시간 늘림 / C 동선 단축 | 기획+레벨 |

| **M11** 감지 즉시 포획 | 감지 범위(150+15cm) 안 + 길이 열려 있으면 바로 포획. 원래 기획은 감지 → 추적 → 몸 닿으면 포획 | 즉시 포획 구역으로 확정할 것인가 | A 현행 유지 + 정확히 안내 / B 감지·추격·접촉 포획 분리(대규모 재검증) | 기획+AI+연출 |

## 2. 나중에 결정해도 되는 것

| 안건 | 현재 구현 | 결정할 것 |
|---|---|---|
| **M04** 튜토리얼 방울 범위 | 튜토리얼 650 / 본편 500 (벽 관통 아닌 경로 감쇠 예산) | 튜토리얼만 넓게 유지하고 알려줄지, 본편과 통일할지 (줄이면 튜토리얼 유인 배치가 깨질 수 있음) |
| **M05** 움직이는 갑옷의 소리 청취 | 소리가 난 순간의 갑옷 위치로 청취·도착 시각을 미리 정함 | 현행 공식화 / 파동이 실제로 닿을 때 듣도록 변경(계산·동기화 추가) |
| **M06** 바구니·캣홀 체류 | 바구니: 들어가는 순간 안전, 실루엣·수색 없음. 캣홀: 체류 제한 없음. 기다리는 동안 시간은 흐름 | 시간 비용만으로 충분한지 플레이로 먼저 확인 → 필요할 때만 표시·제한 추가 |
| **M08** Stage1 시간 저장 손실 | 퍼즐·전환·메뉴·정상 종료 때만 저장, 주기 저장 없음 → 강제 종료 시 마지막 저장 뒤 쓴 시간이 복구됨 (Stage1만 해당) | 허용할 손실 범위, 주기 저장 도입 여부 |
| **M09** Stage3 마무리 범위 | 맵·동상 2·봉쇄 장치 3·최종 대문·완료 화면 구현, 1→2→3 연결(승강기 포함) 자동화 검증. **바구니 없음, 전용 엔딩 연출 없음**, 손으로 끝까지 완주 미검증 | 적 밀도·제한시간·실패/저장 정책, 바구니 추가 여부, 엔딩 연출 범위·담당·기한 |
| **M10** 정식 맵 vs 테스트 맵 | SoundTest_Tutorial/Stage2에는 캣홀 방울 금지 구역이 없음 (정식 1/2개) | 테스트 맵을 동기화할지, 차이를 명시한 실험 맵으로 둘지. 출시 검사는 정식 맵으로 고정 권장 |

## 3. 회의 없이 진행할 기술 작업

1. 정식 맵에서 HUD·미니맵·설정 확인창·스태미나·시간 동작을 실제 입력으로 확인
2. 무적·순간이동 없이 튜토리얼→Stage3 연속 완주 (M01·M02·M09 판단 근거)
3. Shipping 패키지 빌드·실행, 목표 PC에서 프레임·메모리 측정
4. 자동화는 종료코드가 아니라 결과 파일의 성공/실패 수로 판정
