# Stage3 벽 가림 및 밀기 공간 수정 — 2026-11-25

적용 맵: `/Game/Maps/Stage3` (`Content/Maps/Stage3.umap`).

## 수정

- 벽 판정에서 모든 축으로 90cm 부풀린 bounds와 고양이 뒤쪽으로 연장한 검사를 제거했다. 실제 직교 카메라 방향, 고양이 캡슐 중심, 화면상 반경 24cm의 9개 전경 ray를 사용한다. 장식이 튀어나온 범위 대신 벽 본체 bounds를 공유한다.
- 성문 프레임의 빈 문틀까지 채우는 큰 합성 bounds를 제거하고 Stage3 전용 불투명 재질을 연결했다. 기존 상호작용 장치의 불투명 재질은 유지한다.
- P1 무게추 시작 위치를 월드 `(-700,-1430,0)`에서 `(-700,-1510,0)`으로 옮겼다. 뒤 간격은 40cm에서 120cm가 됐다. 고양이 캡슐 지름은 40cm이다. 부착된 무게추 시각 메시와 받침도 함께 이동했다. 배치 원본 `Scripts/Stage3/layout.py`에도 반영했다.
- P2 뒤 간격은 약 115cm로 충분하여 배치를 유지했다.

벽/바닥 구조, 두 퍼즐의 발판·문·설정·참조, 카메라 방향, 순찰 경로, 공유 머티리얼과 Stage1·2는 이 수정으로 변경하지 않았다.

P1은 충돌 검사된 통로에서 뒤로 걸어 들어간 뒤 61.77cm 밀렸다. P2는 접근 중 자연스럽게 5.56cm 밀리고, 본 밀기 단계에서 추가 60.89cm 밀렸다. 직접 `TryPushStatue` 호출이나 접촉 위치로 반복 텔레포트하는 방식을 사용하지 않았다. 각각 옆으로 걸어 나와 리셋 후 저장된 시작 위치와 발판 상태가 복원되는 것도 확인했다.

수정 전에는 P1 뒤로 걷는 동작이 실제 뒷벽에서 막혔다. 기존 검사 위치는 고양이 캡슐이 벽에 약 5cm 침투한 상태였다. 새 baseline 실행은 이 막힘을 재현했다. 이어지는 P2 검사에서는 정상 접근 중 자동으로 밀리는 것을 금지한 검사 조건이 실패하여, 정상 접촉 이동을 기록하고 별도 60cm 밀기를 요구하도록 검사 도구를 고쳤다. baseline 전체를 통과한 것으로 집계하지 않는다.

1,452개 액터 중 위치 변경은 승인된 P1 관련 3개뿐이며 나머지 1,449개 변환은 동일하다. 충돌·메시·부착 관계·순찰 경로 및 native 액터 설정을 보존했다. 보호 에셋 884개는 불변이다. 동시 작업 중인 `CatrunElevatorTransition.cpp/.h` 변경은 별도 작업으로 구분했다.

GPU의 후경 벽 `S3_Wall_0078`은 불투명 기준과 가림 활성화 상태 모두 10,473픽셀이며 픽셀 영역 차이가 0이다. 전경 벽 `S3_Wall_0079`는 10,420픽셀에서 0픽셀로 바뀌어 정상적으로 제거된다. 실제 저장 MI와 custom primitive data를 그대로 사용했다. 다른 두 후보 벽은 해당 테스트 카메라에서 불투명 기준도 0픽셀이어서 GPU 검사 대상에서 제외했으며 통과로 집계하지 않았다. 해당 판정 수학은 CPU 회귀 범위에 포함된다.

검사 도중 별도 엘리베이터 작업에서 Stage3 입구에 도킹 구조물을 추가하고 `S3_Wall_0001/0002`를 숨겨 대체했다(`Scripts/ElevatorTransition/author_scene.py` 및 해당 작업의 성공 보고서 확인). 이것이 위 두 표본이 미노출된 이유다. 최종 입구 화면의 새 도킹 구조물은 이 벽/밀기 수정의 산출물이 아니다. 직접 적용 직후의 범위 검사와 이후 동시 작업이 포함된 플레이 화면을 구분한다.

증거 폴더: `Saved/Stage3ReadabilityPushFix20261125/`. `applied.json`, `scope_audit.json`, `PushRegression/after01/report.json`, `GPU_after04/report.json`, `QA/before` 및 `QA/after`를 보존했다. 원본 맵과 재질 백업은 같은 폴더의 `Backup`에 있다. 초기 GPU 검사 도구의 지원하지 않는 속성/commandlet 전용 함수 호출 오류와 미노출 표본도 각 이전 보고서에 남겼다. 최종 GPU 검사는 엔진 소스에서 확인한 SceneCapture 속성과 전체 에디터의 컴파일 대기 명령을 사용한다.

최종 전체 회귀 증거는 `Saved/Stage3OrientationFix20261125/ReadabilityPushFix01/report.json`이다. 두 발판을 통한 native 퍼즐 진행, 3개 당김 장치 및 중단/일시정지, D0 양방향, D1/D2 개방, 통로 보행, 성문 600cm 통로 개방, 최종 출구 실제 도보 완료를 확인했다. 실제 카메라 yaw는 -135°로 유지했다. 플레이 화면은 위 증거 폴더의 `before`/`after`에 같은 4개 위치로 저장했다.

이 검사는 별도 PIE에서 NPC 충돌/틱을 정지한 재현 가능한 접근·퍼즐 검사다. 적을 피하며 전 구간을 직접 플레이한 난이도 검증을 의미하지 않는다. 이번 수정에서는 C++ 게임 로직을 변경하거나 GitHub에 새로 푸시하지 않았다.
