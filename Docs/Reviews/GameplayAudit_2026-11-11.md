- 이번 실행의 Unreal MCP가 `/Game/Maps/MainMenu`를 반환했다. 실제 PIE 메뉴에서 마우스로 설정을 열고 적용했으며, 적용 버튼 밑줄이 포인터 이탈 후 사라지고 Escape로 메뉴가 복원되는 것을 확인했다. 메뉴 로고가 설정 글자와 겹치지 않았고 발자국은 원래 비율로 보였다.
- Live02: 메인 메뉴의 시작 버튼을 실제 클릭했다. `Saved/GameplayAudit20261111/MenuStart/observations.json`은 인트로의 실제 재생·고양이 바인딩·원래 안내 표시·게임플레이 카메라/조작 복귀를 통과했다.
- Tutorial: 일반 Enhanced Input 이동과 실제 F 키로 바구니 진입 → 숨기 → 탈출 → 착지 후 이동을 확인했다. 동쪽 우회 → 캣홀 통과도 확인했다. 표식 상태로 캣홀 밖에서 기다린 두 시도는 포획됐고, 인트로 없이 시작점으로 재시작했다. 그중 기록된 갑옷/고양이 좌표 사이의 현재 맵 단순/복합 충돌 선을 조회했으며 차단체가 없었다(`tutorial-capture-geometry.json`). 열린 우회 경로의 포획을 벽 너머 포획 결함으로 취급하지 않았다.
- Stage2: 별도로 맵을 열고 원래 시작 위치에서 일반 이동 입력만으로 C 동상을 X/Y 방향으로 밀어 안착시켰다. 적 비활성화·순간이동·강제 해결은 사용하지 않았다. 문 이동 약 2.99초, 열림 약 2초, 복귀 약 2.50초, 철창 -280cm, 원래 카메라와 입력 복귀를 기록했다. 이어 실제 캐릭터가 열린 문을 통과했다. 촛불 3개는 각 순찰 축에서 약279.47cm의 위치 범위를 보였다. `Saved/GameplayAudit20261111/stage2-runtime-summary.json`과 `runtime-summary.json`에 기록했다.
- Stage1: 별도로 정상 시작점에서 검사했다. 첫 보관실 바구니로 가려던 직접 경로와 아래쪽 우회 경로는 순찰 갑옷에게 잡혔다. 따라서 이번 실제 플레이에서 Stage1 첫 바구니·포털 도달이나 추격 중 바구니 탈출을 통과했다고 주장하지 않는다.
- **메인 메뉴 → 튜토리얼 → Stage1 → Stage2 전체 연속 완주는 확인하지 못했다.** 국소 검사나 자동 회귀 성공을 전체 완주로 취급하지 않는다.

## 실제 화면에서 남은 문제

- Stage1 시작점 `(880,2320)`에서 전경 벽이 고양이를 많이 가려 이동 방향과 주변 상황을 읽기 어렵다. 시작/포획 재시작 화면에서 관찰했다. 카메라의 공통 가림 처리 또는 전경 벽 표현을 검토할 대상이다. 특정 벽 충돌을 없애거나 임의 투명화하는 수정은 이번 범위에 추가하지 않았다.
- Stage1 화면에 `RAY TRACING GEOMETRY - ALWAYS RESIDENT MEMORY EXCEEDS 20% OF THE BUDGET (108.395 MB / 400 MiB)`가 표시됐다. 렌더링 예산/상주 지오메트리 프로파일링 대상으로 기록한다. 이 경고만으로 실제 프레임 저하나 크래시 원인을 확정하지 않았고, 전역 렌더링 설정을 임의 변경하지 않았다.

## 남은 조건부 위험과 추가 검증 대상

아래는 소스·저장 그래프에서 확인한 실패 처리 경로다. 현재 정상 맵에서 발생한 플레이 실패라고 주장하지 않는다. 이번 변경 범위 밖이며 별도의 장애 주입 검사가 필요하다.

1. 튜토리얼 계단에서 다음 맵 요청이 거절되거나 로드에 실패하면 BP가 소유한 이동/카메라 잠금을 복구하는 분기가 없다. 성공 시 원래 계단 연출은 유지하면서 실패 콜백과 소유권 단위 정리가 필요하다.
2. 포획 재시작의 OpenLevel 요청 실패 시 기존 월드에 암전과 포획 상태가 남을 수 있다. 요청 수락/실패와 재시작 의도 소유권을 구분하는 별도 수정이 필요하다.
3. 목적지 도착 체크포인트 저장이 실패하면 이전 스테이지 저장은 보존되지만 플레이 화면에 실패가 표시되지 않는다. 저장 대기 중 메뉴로 돌아올 때 이어하기 버튼/설명이 완료 상태를 다시 읽지 않는 경우도 있다.
4. 기본 Windows 단일 저장 파일을 덮는 중 프로세스가 중단되면 메모리에 둔 이전 바이트로 복구할 수 없다. 원자적 파일 교체 또는 마지막 유효 저장 사본을 사용하는 저장 백엔드 검토가 필요하다.

갑옷의 복귀 경로 실패 후 Idle로 남는 정책은 기존 테스트가 명시적으로 정한 동작이다. 이번 감사에서 임의로 더 똑똑한 추적·복귀 정책으로 변경하지 않았다. 바구니의 모든 출구가 막히는 배치, 동상 리셋 콜백이 위치를 바꾸는 상황 등은 실제 맵 재현 근거가 없어 확정 결함과 분리했다.
