## 판단

**핵심 기능을 시험할 수 있는 프로토타입이다. 시작부터 탈출까지 완주하며 게임 전체를 평가하는 버전은 아직 아니다.**

소리 전파·갑옷 이동·촛불 감지·바구니·연출에 재사용할 구현이 상당히 있다. 현재 가장 큰 공백은 기능이 부족한 것뿐 아니라 **본편 맵과 기능 테스트 맵의 분리, 실제 규칙과 기획서의 불일치, 종료 조건 부재**다. 전면 재작성보다 기준 플레이 루프를 정하고 기존 구현을 한 맵에 통합하는 편이 합리적이다.

기획서 기준은 `Docs/Design/GameDesign_Source.md`다. 일부 코드는 그 기획서 이후의 변경을 명시하므로, 차이를 전부 버그로 취급해서는 안 된다.

## 우선 해결할 문제

### 1. 게임 시작 경로가 핵심 시스템을 거치지 않음 — 통합 공백

일반 Tutorial → 일반 Stage1에는 적·소리 관리자가 없다. 테스트 맵에는 같은 시스템이 따로 존재한다. 기능별로 정상이어도 메뉴부터 시작한 사람이 게임의 핵심을 체험하지 못한다. 실제 배포 시 기본 시작 맵도 템플릿 OpenWorld다.

### 2. 유인 후 우회라는 규칙이 현재 AI와 다름 — 설계 결정 필요

기획은 조사 이동 중 더 큰 소리만 수용하여, 大 방울로 유인한 뒤 中 달리기로 도망칠 수 있게 한다. 현재 `CatrunArmor.cpp:118`은 변경 사항으로 **모든 새 소리를 수용**한다고 명시한다. 따라서 발소리가 기존 방울 목적지를 덮어쓸 수 있다. 소리 조사의 목표가 실시간 고양이 좌표를 직접 읽는 버그는 아니지만, 연속 발소리로 비슷한 추적 결과가 나올 수 있다.

또한 감지 원에 들어오면 `CatrunArmor.cpp:683`에서 바로 `StartCatch`를 호출한다. 기획의 감지 추적 → 실제 접촉 시 잡기와 다르다. 이번에 읽은 DA의 감지 반경은 150cm다.

이는 코드가 문서 이후 변경된 흔적이므로, 원문으로 되돌릴지 현재 규칙을 채택할지 먼저 결정해야 한다.

### 3. 속도와 방울 동작의 조합 — 밸런스 위험

읽은 BP/DA의 기본값은 다음과 같다. 임의의 레벨 블루프린트가 실행 중 별도 변경하는 경우까지 검증한 것은 아니다.

| 항목 | 값 |
|---|---:|
| 고양이 살금살금 / 걷기 / 달리기 | 48 / 74 / 119 cm/s |
| 배치 갑옷 순찰·복귀 | 150 cm/s |
| 갑옷 일반 소음 / 방울 / 표식 달리기 | 200 / 250 / 300 cm/s |
| 방울 입력 후 AI 소리 이벤트 | 약 0.567초 |
| 방울 입력 후 이동 복구 | 2.8초 |
| 방울 재사용 | 5초 |

갑옷의 순찰부터 고양이 달리기보다 빠르다. 방울은 약 2.23초 동안 AI에 이미 들리지만 고양이는 아직 움직이지 못하는 구간도 있다. 여기에 작은 발소리로 목적지가 바뀌는 규칙이 더해지면 유인의 이득보다 노출 손해가 클 수 있다. 불가능하다고 단정할 수는 없으며, 반응 애니메이션·소리 도달 시간·실제 우회 동선까지 묶어 플레이테스트해야 한다.

### 4. Stage2 테스트 맵에는 표식 해제 수단이 없음 — 레벨 공백

`SoundTest_Stage2`는 갑옷 4기·촛불 3기가 있으나 상호작용 가능한 바구니가 없다. 표식 해제 코드는 바구니 진입을 전제로 한다. 현재 배치로는 그 맵 안에서 의도한 해제 루프를 검증할 수 없다. 죽어 레벨을 재로드하면 표식은 초기화되지만, 이는 정상 탈출 전략을 대신하지 않는다.

### 5. 성공·시간·재시작이 닫히지 않음 — 전체 플레이 공백

각성도와 성문 공략 시스템이 연결돼 있지 않고, 현재 실패 처리는 현재 레벨 재로드다. 그러므로 각성도 유지, 체크포인트 복구, 성문 진행도, 스테이지 완료를 포함하는 전체 플레이를 평가할 수 없다.

기획 자체에도 “각성도 최대 실패 후 그 값을 유지하면 즉시 재실패”하는 모순이 보존돼 있다. 구현 전에 이 재시작 규칙을 확정해야 한다.

## 대규모 수정 시 조심할 구조

아래는 정적 코드 검토에서 확인한 위험이다. 실제 플레이 중 재현된 장애로 제시하는 항목은 아니다.

1. **표식 담당 갑옷 선정:** `CatrunMarkSubsystem.cpp:100`부터 직선 거리로 가장 가까운 1기를 고른다. 우회 거리·접근 가능성을 검사하지 않아, 접근 불가능한 갑옷이 담당자로 남고 다른 갑옷이 오지 않을 수 있다.
2. **지연 소리 판정:** `SoundGridManager.cpp:217`부터 발생 순간의 청자 위치로 도달 여부를 예약한다. 도착 시점의 위치·문 상태를 다시 계산하지 않는다. 소리가 이동하는 동안 적이 움직이거나 문이 변했을 때 보이는 파문과 AI 반응의 기준이 달라질 수 있다.
3. **막힘을 도착으로 처리:** `CatrunArmor.cpp:912`는 기본값 기준 약 2.4초 이상 막히면 목표까지 멀어도 도착 처리한다. 가구·문 위치를 바꾸면 조사 중 포기처럼 보이는 동작이 생길 수 있다.
4. **문자열로 플레이어 상태 탐색:** `CatrunCatQueries.cpp:22`, `CatrunCatStateComponent.cpp:23` 등은 클래스 이름 `CatActions`, 변수 `IsHidden`, `Busy`, `IsRunning`, `IsSneaking` 등을 문자열로 읽는다. BP 이름·상태 구조를 바꾸면 빌드 성공 상태에서도 은신·발소리 판정이 조용히 깨질 수 있다.
5. **튜닝 값 중복:** 실제 방울 입력 BP는 5초 상수를 사용하고 C++ fallback은 `DA_SoundSettings.BellCooldown`을 사용한다. 고양이 속도도 BP 상수, 갑옷 달리기는 DA, 갑옷 걷기는 액터 속성에 분산돼 있다.
6. **공간 데이터 의존성:** 바닥/벽/장애물 태그, 충돌 설정, 2D 그리드·단일 높이에 의존한다. 동적 지형이나 다층 구조로 바꾸면 현재 접근 자체를 재검토해야 한다. 벽·바닥을 바꾼 뒤 저장된 그리드가 이미 유효하면 자동 재베이크를 기대할 수 없다.
7. **성능 미측정:** 감지용 다수 레이와 텍스처 갱신이 매 프레임 수행되고, 각 소리에서 전파를 판정용·표시용으로 두 번 계산한다. 현재 적 수에서 느리다고 확인한 것은 아니지만 적·소리 빈도를 늘리기 전에 계측이 필요하다.

## 로그와 검증상의 주의

- 이번 로드에서는 과거의 삭제된 Ripple 컨트롤러 패키지 누락을 재현하지 않았다. 현재 테스트 맵 3개에 새 경로 컨트롤러가 존재하며 BP도 컴파일된다. 과거 진단을 현재 결함으로 복사하지 않았다.
- `BP_CatActions`의 주석 노드에 NodeGuid 누락 경고가 있다. PIE 시작을 막지 않았지만 결정적 쿠킹 관련 경고이므로 패키징 전에 점검할 대상이다.
- PIE마다 `SpawnActor failed because no class was specified` 경고가 있었다. 고양이 인스턴스는 존재한다. 경고 원인은 이번 범위에서 확정하지 않았다.
- 초기화 중 `LogAutomationTest: Error: Condition failed`가 반복되지만, 인근 로그는 엔진의 `UnifiedErrorTest` 진단 코드다. 별도로 실행한 Catrun 테스트 결과는 성공 6개다. 초기화 문자열만으로 프로젝트 테스트 실패로 판단하지 않았다.
- 테스트가 보장하는 것은 계산·방향 등 제한된 범위다. 갑옷 상태 전환, 표식 해제, 잡기/재시작, 성문, 전체 진행에 대한 자동 회귀 검증은 없다.

## 다음 작업의 권장 순서

1. 원문과 현재 구현 중 **소리 덮어쓰기 / 감지 즉시 잡기 / 속도 / 캣홀 방울 금지 / 각성도 실패 후 값**을 어떤 규칙으로 가져갈지 결정한다.
2. `SoundTest_Stage1`을 기반으로 3~5분짜리 한 구간을 지정하고, 유인 → 우회 → 발각 → 바구니 해제 → 목표 도달 → 성공/재시작을 연결한다.
3. 그 구간을 메뉴에서 바로 시작하도록 구성해, 일반 맵과 테스트 맵의 진행 경로를 통합한다.
4. 방울 없이 통과 가능한지, 작은 소리 때문에 유인이 무효가 되는지, 표시와 감지가 일치하는지, 바구니·캣홀로 무한 버티기가 되는지 실제 입력으로 검증한다.
5. 한 구간의 재미와 실패/재시작이 성립한 뒤 각성도·성문 공략과 Stage2를 확장한다.

위 순서는 제안이며 이번 점검에서 구현 변경은 하지 않았다.
