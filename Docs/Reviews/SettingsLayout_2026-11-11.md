# 설정 레이아웃·밑줄·발자국 수정

사용자가 옵션 레이아웃 깨짐, 옵션 변경 후 남는 밑줄, 우상단 발자국의 가로 압축을 신고했다. 글꼴 손상이 아니라 배치와 강조 상태 문제로 재현됐다.

## 원인과 수정

- 적용 버튼을 마우스로 클릭한 뒤 창 크기가 바뀌어 포인터가 버튼 밖에 있어도, 기존 Blueprint가 클릭으로 남은 키보드 포커스를 호버와 같은 강조로 처리했다. 기존 설정 입력 전처리기에 사용자별 마우스/탐색 표시 상태를 추가하고 `IsNavigationFocused`로 판정한다. 실제 포커스와 입력 전달은 유지한다. 설정 17개·메인 메뉴 4개 컨트롤의 BP는 호버, 선택 탭, 키 입력 대기 조건을 유지한다.
- 설정 뒤에서 메인 메뉴의 로고와 버튼 문구가 그대로 비쳐 조작 설정 글자와 겹쳤다. 옵션 버튼과 메인 메뉴 Escape 경로에서 기존 메뉴를 숨기고, 닫을 때 원래 가시성과 활성 상태를 복원한다. 게임 중 HUD는 이 숨김 대상이 아니다.
- `SettingsPawBounds`는 36×36이지만 바깥 가로 행의 슬롯이 세로 Fill이라 제목 높이까지 늘어났다. 바깥 슬롯만 세로 Center로 변경했다. 정사각형 원본 `CatJelly`, 내부 Fill, 크기, 색상은 유지했다.
- 향후 메뉴 작성 스크립트도 같은 판정을 사용한다. 인트로, 튜토리얼 안내, 맵, 기존 시네마틱은 이 수정에서 변경하지 않았다.

## 검증과 한계

- 수정 전 실제 메뉴에서 적용 후 밑줄 잔류, 뒤쪽 메뉴 글자 겹침, 발자국 늘어남을 관찰했다. `Saved/FullPlayAudit20261111/Live01/`에 상태와 엔진 화면 기록이 있다.
- `FullPlayAuditUI20261111_01` C++ 빌드 성공. `FullPlayAuditUITests20261111_01/AutomationReport/index.json`은 77개 통과(75개 성공, 기존 경고 포함 성공 2개), 실패 0개다. 새 `NavigationFocusPresentation`, `SourcePanelStateRestoration`은 경고 없이 통과했다. 기준 경로는 `Saved/GameplayRepair20261105/`다.
- 첫 에셋 저장 실행 `Saved/Menu20261105/author-1111.log`는 저장 이후 같은 프로세스의 ReloadPackage에서 엔진 FindInBlueprintManager ensure가 발생했다. 이 실행을 깨끗한 검증 성공으로 취급하지 않는다. 작성 스크립트는 저장과 별도 프로세스의 읽기·컴파일 검증으로 분리했다.
- 사용자가 컴퓨터 사용을 위해 플레이 검증을 중단시켰다. 이후 Computer Use, PIE, 화면이 뜨는 에디터를 다시 실행하지 않았다. 수정 후 실제 마우스 조작·화면 모양 검증은 미완료다. 두 에셋의 새 프로세스 검사 결과는 아래 최종 기록과 HANDOFF를 따른다.
- 중단 전 원래 MainMenu 시작 → Tutorial 인트로·안내·조작 복귀, 인게임 Esc 열기/닫기, 일반 이동·캣홀 통과, 포획 후 인트로 없는 시작점 복귀를 관찰했다. 촛불 표식으로 포획된 시도도 있었다. Stage1/Stage2 완주, 추격 중 바구니 전체 검증은 하지 못했다. 실패한 이동 경로만으로 게임 결함이라고 단정하거나 게임 로직을 변경하지 않았다.
- 새 게임 테스트로 변경된 진행 저장은 이전 바이트로 복원했다. GameUserSettings와 Input 파일도 최초 해시와 일치한다. 기존 로컬 시네마틱·갑옷 수정은 보존한다. 커밋·푸시하지 않았다.

## 최종 저장 검사

`author-1112.log`의 저장 상태 기록과 `author-1113.log`의 별도 프로세스 검사가 모두 종료코드 0·오류 0으로 끝났다. 최종 근거는 `Saved/GameplayRepair20261105/SettingsAffordances20261111/run-20261111T041913882955Z/audit.json`이다. 두 위젯이 UpToDate로 컴파일되고 21개 표시 연결, Center/36×36 발자국, 원본 텍스처·색상, 보호 에셋 해시가 일치한다. 최종 검사는 에셋을 저장하지 않아 파일 해시도 유지됐다. 같은 프로세스의 재로드 ensure는 재발하지 않았다. 기존 MCP 라이선스 고지와 Python enum/델리게이트 이름 중복 경고 2개는 남아 있으며, 이번 위젯의 컴파일 경고는 없다.
