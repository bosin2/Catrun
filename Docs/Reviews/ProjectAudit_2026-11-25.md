# Catrun 전체 프로젝트 점검 — 2026-11-25

## 결론

튜토리얼·Stage1·Stage2의 핵심 시스템은 존재하지만 **전체 게임 제작·최신 확장 기능의 실플레이 수용까지 완료된 상태는 아니다.** 가장 큰 문제는 오래된 기획 문서, 정식/테스트 맵의 규칙 차이, 최신 기능 통합 중의 검증 실패·검사 공백이다. 기획이 필요한 차이와 재현된 테스트 실패를 구분했다.

이번 요청에 따라 기획 문서를 수정했다. 게임 코드·맵·에셋·사용자 저장 파일을 이 감사에서 수정하지 않았으며 커밋·푸시도 하지 않았다. 병행 개발 채팅의 변경은 별도로 관측한 결과로 기록한다.

### 2.2 재검사와 프로세스 간 저장

## 3. 문제와 수정 우선순위

### F01. 최신 기능의 테스트 수용 실패 및 실행물 불일치 — 검증 우선

초기 실제 자동화3개 실패와 별도 저장 검사0개 실행을 확인했다. 실패 원인이 테스트 구성인지 제품인지 구분하지 않고 “전체 통과” 또는 “게임이 고장났다”로 발표하면 모두 잘못이다. 최신 빌드 후 동일 조건 재검사, 실제 플레이어/이동을 사용하는 검사, 새 프로세스 슬롯 복원이 필요하다. 최종 상태는 2.2절을 따른다.

근거: `Interaction/Tests/StatuePuzzleTests.cpp`, `Sound/Tests/CatFootstepCadenceTests.cpp`, `Player/CatrunSprintComponent.cpp`, `LevelFlow/CatrunLevelFlow.cpp`, `LevelFlow/Tests/StageProgressProcessTests.cpp`.

### F02. 정식 맵과 테스트 맵의 방울 규칙이 다름 — 확인된 시스템 구성 차이

Tutorial/Stage2의 정식 맵에는 각각1/2개의 `CatrunNoBellZone`이 있는데 대응 SoundTest에는0개다. `CatrunNoBellZone::IsBellForbidden`은 실제 배치 영역을 순회하므로 캣홀 금지를 검증할 조건 자체가 다르다. 정식 맵에서의 금지가 깨졌다는 뜻은 아니지만, 테스트 맵 성공을 제품 수용으로 삼을 수 없다.

**권고:** 출시 수용은 정식 맵으로 고정하고 테스트 맵을 동일 사본으로 유지할지 실험용으로 구분할지 결정한다. 맵 수정은 이번 감사에 포함하지 않는다. 회의 M10.

### F03. 촛불의 실제 감지와 시야 설명이 완전히 일치하지 않음 — 확인된 논리 차이

`CatrunCandle::CheckForCat`은 원뿔 감지 외에45cm 접촉 감지를 허용한다. 시야 디스플레이는 `SetNearClip`과 각도 원뿔로 생성한다. 원뿔 밖 뒤/옆에서도 근접하면 표식이 생길 수 있는데 원문은 표시와 판정이 완전히 같다고 요구한다.

**확인 수준:** 코드 조건과 실제 DA45를 확인했다. 이번에는 실제 화면의 특정 지점에서 표시 밖 발각을 손플레이로 재현하지 않았다. **권고:** 접촉 감지를 공식화하고 표시/설명을 추가하거나 시야만 사용한다. 사용자 판단 없이 감지 코드를 바꾸지 않는다. 회의 M03.

### F04. 오래된 문서를 따르면 잘못 구현하게 됨 — 문서 수정

기존 GDD·PlayFlow·Stage2 문서는 서로 다른 시점의 내용을 현재형으로 안내했다. 주요 오해는 SoundTest를 정식 경로로 안내, 모든 실패 시 퍼즐 초기화, C체크포인트, 복구장치F, 동상 이탈 시 문 닫힘/문 상승, 전역 각성도, 이미 구현된 AI를 미구현으로 표시한 부분이다.

**조치:** 현행 전체 기획서 작성, 현재 동선/퍼즐 문서 갱신, 오래된 조정·설계 제안 문서에 현행 문서 안내 추가. 최초 사용자 원문과 과거 실행 기록은 보존했다.

### F05. 최신 HUD의 중간 적용 실패 — 작업 중 기록, 현재 최종 결함으로 단정 금지

`asset-integration02/03.json`에는 UMG 도구 초기화/위젯 조회의 AttributeError가 있다. 이후 `asset-integration04.json`에서 player resources·HUD·Tutorial/SoundTest_Tutorial/MainMenu passages 단계 완료를 확인했다. 따라서 중간 실패를 “현재 HUD 없음”으로 보고하지 않는다.

**남은 조건:** 실제 게임에서 상태바/미니맵/설정 확인창/암전/제목/포커스를 수용해야 한다. 에셋 존재와 작성 스크립트 완료는 화면 품질 또는 전체 흐름 성공의 증거가 아니다.

### F06. 비정상 종료 때 남은 시간 롤백 범위가 정해지지 않음 — 설계/검증 공백

`AdvanceClock`은 메모리 값을 줄이고 dirty 표시를 한다. 영구 완료·전환·메뉴·정상 종료 때 저장하지만 일정 주기의 flush 호출은 확인되지 않았다. 저장 사건 사이에서 강제 종료하면 그동안 줄어든 시간이 복구될 수 있다. 정상 종료 저장의 실패와는 다른 조건이다.

**권고:** 허용 롤백 기간과 조용한 저장 주기를 정한다. 자동 저장을 무조건 추가할 결함으로 단정하지 않는다. 회의 M08.

### F07. 성능·패키지·전체 완주 수용이 남아 있음 — 출시 판단 차단

이번 검사는 NullRHI 논리 검사와 읽기 전용 에셋 로드다. GPU/실제 프레임 비용이나 최종 패키지는 검사하지 않았다. 시야는 매 프레임 ray texture 갱신/UpdateResource를 사용하고, 발음 때 격자 전파를 청각/시각용으로 각각 계산한다. 비용 가능성이 있으나 현재 성능 버그·누수라고 결론 낼 측정은 없다.

**권고:** 정식 맵의 목표 하드웨어에서 프레임·메모리·로딩/저장·시야 경계를 측정한다. 과거 DX12 대량 자동화 실패를 현재 GPU 메모리 부족 확정으로 재사용하지 않는다.

### F08. 갑옷의 감지와 접촉 포획이 분리되어 있지 않음 — 확인된 기획/코드 차이

원문은 감지 범위에서 추적을 시작하고 몸이 닿으면 잡도록 되어 있다. 현재 `CatrunArmor::UpdateDetection`은 원형 감지+차폐+몸체 통과 검사를 통과하면 바로 `StartCatch`를 호출하고, `BeginCapture`는 즉시 이동/입력을 잠그며 포획 연출을 예약한다. 별도의 접촉 거리 확인은 없다.

현재 실제 범위는 공유150cm에 고양이 판정 반경15cm가 적용된다. 철창 차단 보완과 별개로, 열린 공간에서는 접촉 전에도 포획할 수 있다는 의미다. **권고:** 즉시 포획 구역인지, 감지 추격과 접촉 포획을 분리할 것인지 M11에서 결정한다. 현재 기획서에는 구현을 명시하고 의도 확정은 보류했다.
