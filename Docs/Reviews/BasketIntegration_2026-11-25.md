# 스테이지별 바구니 적용 및 쿼터뷰 탈출 검증

2026-11-25. 사용자 승인: 기존 바구니 교체, 다방향 진입, 쿼터뷰 화면 기준 W/A/S/D 단일 키 탈출 방향 선택, 경량화. 스테이지 3은 에셋 임포트만 수행했다.

## 적용 범위

| 저장 맵 | 외형 | 교체한 바구니 |
|---|---|---:|
| Stage1 / SoundTest_Stage1 | 라탄·아이보리 린넨 | 각각 2개 |
| Stage2 / SoundTest_Stage2 | 호두나무 유물함·청회색 천 | 각각 3개 |
| Tutorial / SoundTest_Tutorial | 스테이지 1 린넨 | 각각 1개 |

기존 바구니 액터의 식별자·위치·회전·스케일과 외부 메시 연결을 유지했다. 배치된 메시를 교체하고 사용하지 않는 내부 중복 메시를 비웠다. 저장 시 바구니 이외 액터의 클래스·위치·회전·스케일·태그를 비교했다. 튜토리얼의 레이아웃과 인트로는 변경하지 않았다.

`BP_HideBasket`의 기본 표시도 스테이지 1로 연결했다. 새 에셋은 다음 Content Browser 폴더에 있다. 검색어: **BasketVariants20261125**.

`/Game/Environment/Shared/Castle/Props/Hiding/BasketVariants20261125`

스테이지 3은 `Stage3/Meshes/SM_HideBasket_Stage3`, `SK_HideBasket_Stage3_Cloth`이다. 이번 작업에서는 스테이지 3 맵을 만들거나 배치하지 않았다.

신규 패키지 57개: 몸체·천 메시 6개, 공유 스켈레톤 1개, 애니메이션 18개, 텍스처 24개, 재질 8개. 기존 HideBasket 원본 에셋과 BlackCat 소스는 교체하지 않았다.

## 조작과 성능

- 기본 키 W/A/S/D는 카메라 기준 위/왼쪽/아래/오른쪽이다. F로 선택 출구를 확정한다. 바구니 회전으로 출구 벡터를 보정하거나 45도로 양자화하지 않는다. 기존 키 재설정 경로도 사용한다.
- 뒷면 금지를 없앴다. 진입 위치는 실제 접근 위치와 8개 연출 구역으로 정하고, 출구는 정확한 카메라 축을 따른다. 천의 8방향 클립 선택과 플레이어 입력 방향은 별개다.
- 활성 바구니의 선택 출구만 검사한다. 방향 변경과 F 확정은 즉시, 같은 방향에서 동적 장애물 확인은 0.2초 간격이다. 확정·착지 시 캡슐 경로, 바닥, 원래 충돌 프로파일을 다시 확인한다.
- 바구니 목록은 초기화 시 수집하고 스폰 이벤트로 추가한다. 바깥의 상호작용 검색은 0.15초 간격으로 가장 가까운 후보의 접근 경로를 검사한다.
- 바구니 액터 상시 틱과 천 물리 시뮬레이션을 사용하지 않는다. 천은 진입·탈출 중에만 틱을 켜고, 비어 있거나 은신 중에는 정지 포즈로 둔다. 외부 천의 초기화 순서 차이는 시작 직후 한 번의 약한 참조 콜백으로 정리한다.
- 점프 중 기존 캡슐 이동·충돌 해제 방식을 유지하며, 실제 캡슐 크기 반지름 20cm / 반높이 24cm로 안전 지점을 검증한다. 대각 연출에는 94cm, 정면에는 82cm 거리를 사용한다.
- Blender의 좌표계가 FBX에서 변환되는 점을 반영해 가져온 기준 본의 앞·오른쪽 방향으로 천 클립 인덱스를 계산한다. 고양이와 천에 같은 재생 속도를 적용한다.

Interchange가 원본 UCX 충돌을 누락한 것을 재로드 검사에서 발견했다. 원본과 같은 치수의 바닥 1개·벽 4개를 저렴한 박스 충돌로 신규 메시 3개에 기록했다. 윗면 충돌은 없다. 저장 후 각 메시의 박스 5개를 다시 읽어 확인했다.

- 최종 CatrunEditor 빌드 성공: `Saved/BasketIntegration20261125/build_startup_fix.log`.
- 네이티브 자동 검사 **15개 성공, 경고 성공 0, 실패 0**: `AutomationFinal3/index.json`. 카메라와 바구니의 다양한 회전, 키 재설정, 막힌 경로, 지면 소실, 늦게 생긴 장애물, 정확한 착지, 취소 복구 및 바구니 제거 직후 F 입력을 포함한다.
- 저장된 6개 맵과 신규 에셋 재로드 검사 성공: `cold_audit.json`. 스켈레톤 공유, 진입 8 / 탈출 8 / 대기 2 클립, 길이, 재질 연결, 충돌 5개를 확인했다.
- 실제 Stage1 바구니 2개와 Stage2 바구니 3개 × W/A/S/D = **20사례 완료**: `PIE/report.json`. F/WASD를 실제 PlayerController 입력 경로로 주입했다. 캐릭터 시작 위치는 검사 편의를 위한 임시 배치이며 저장하지 않았다.
- 막힌 방향 **4건**에서 F가 탈출을 시작하지 않고 은신을 유지했다. 다른 단일 키로 출구를 선택해 정상 탈출했다.
- Stage2 Room4의 D 사례에서 탈출 종료 재검사가 은신 복귀를 선택한 **1건**을 기록했다. 충돌 해제·메시 숨김·점유·대기 천 포즈가 안전하게 유지됐고 W를 선택해 정상 탈출했다. 해당 표본만으로 어떤 개별 장애물이 원인이었는지는 단정하지 않는다.
- 완료된 진입·탈출 **921개 표본**에서 고양이와 천 재생 시간 차이의 최댓값은 **0초**였다. 방향별 클립 이름, 실제 점프 포즈 변화, 최종 위치와 이동·충돌·점유 복구도 확인했다. 위 은신 복귀 시도의 24개 표본은 별도 기록돼 있다.
- 각 사례의 바깥쪽 캡슐 이동 스윕이 몸체 앞에서 멈췄다. 중심으로부터 정지 거리는 약 60.10~76.25cm였다. 대기 중 모든 해당 맵 바구니의 천 틱이 꺼져 있음을 확인했다.

## 검증 범위와 재실행

실제 실행은 DX11 offscreen PIE이며, 별도 UserDir의 복사한 저장 슬롯을 사용했다. 해당 검사 프로세스에서만 갑옷의 포획을 껐고 순찰과 게임 틱은 계속 실행했다. 전체 스테이지 수동 완주, 기본 DX12에서의 전체 플레이, 튜토리얼·SoundTest 맵의 별도 완주는 수행하지 않았다. 이들 복제 맵은 저장 에셋 연결을 재로드 검사했다.

스크립트: `Scripts/BasketIntegration/`. `run_pie.ps1`은 분리된 에디터로 20사례를 재실행하고, `audit_saved.py`는 저장 결과를 읽기 전용으로 검사한다. `BasketRuntimeCommands.cpp`의 입력 도우미는 개발용 자동 검사 빌드에만 포함되며 Shipping에는 들어가지 않는다.

적용 기록과 첫 수정 전 백업: `Saved/BasketIntegration20261125/apply_report.json`, `Before/`. 다른 작업에서 생성·수정한 소스와 맵 변경은 작업 트리에 유지했으며 커밋·푸시는 하지 않았다.
