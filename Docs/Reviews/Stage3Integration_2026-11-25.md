- 활성 제작 채팅의 완료본을 수집했다. Stage2 아트 보정, 바구니 교체, 게임플레이 확장 및 Stage2 중간 저장 취소를 함께 보존한다.

- 사용자 v3 규격과 기존 채팅의 도면 검토를 복원하여 `/Game/Maps/Stage3`를 제작했다. 구체적 기준·조립 보정·미정 사항은 [통합 기준](../Design/Stage3/IntegrationDecisions.md)에 구분했다.
- 두 동상, 세 개 봉쇄 장치, D0/D1/D2, 캣홀 3개, 갑옷 6기·촛불 5기, 최종 대문·출구와 미니맵을 연결했다. Stage1→Stage2→Stage3는 기존 레벨 흐름 시스템을 사용한다.
- 기존 고양이 78본 리그에 2.4초/30fps 고리 당기기 애니메이션을 제작했다. [제작·자체 검증 프롬프트](../Design/Stage3/CatInteraction_ProductionPrompt.md), 소스 `SourceArt/Stage3/BlackCatInteraction`, 엔진 `AN_BlackCat_ReleaseRing`을 남긴다.

## 이번 검사에서 수정한 문제

1. Interchange에서 누락된 24종 메시의 단순 충돌을 보강했다. 개구부는 통행 공간을 보존한다.
2. FBX 좌표 변환에 따른 장치 전면·힌지·문짝 방향을 바로잡았다.
3. 받침대 때문에 접근할 수 없던 장치 고리를 앞으로 배치하고 체인을 연결했다.
4. 기본 Pawn이 없는 게임모드에 맞춰 Stage3 플레이어를 배치하고 Player0 소유를 지정했다.
5. 상호작용 애니메이션을 다른 소유자가 교체할 때 이동 잠금이 남을 수 있던 정리 경로를 수정했다.
6. 촛불 캡슐의 바닥 여유를 기존 Stage2와 동일하게 적용했다. 전시실 순찰이 동상 밀기 경로를 막지 않도록 옆으로 옮겼다.
7. 대문 홀 갑옷이 기둥 받침 가장자리에서 시작하던 배치를 조정했다.
8. 동상 이벤트 enum과 delegate의 Python 노출 이름 충돌을 분리했다. C++·Blueprint의 기존 형식 경로는 유지한다.
9. 창고 고정 촛불 두 기가 보급 상자·장비장과 겹치던 시작 위치를 조정했다. 11기 모두 저장본 캡슐 여유 검사를 통과했다.
10. 보조광·환경광을 보강해 장치 전면과 대문 목재·금속 윤곽을 드러냈다. 원본 텍스처와 색상은 유지했다.
11. Stage2 회귀 스크립트의 노출되지 않은 설정 클래스 접근과 잘못된 Visibility 프로필 추적을 실제 CDO·채널 추적으로 수정했다. 게임 규칙을 검사 편의에 맞춰 바꾸지 않았다.
12. 낮은 장치 몸체가 머리와 고리 접촉을 가리던 문제를 세 장치 전용 접근 페이드로 수정했다. 거리 155cm 밖에서는 원래 표면을 보존하고 105cm 안에서는 몸체를 흐리게 한다. 고리·체인·당김은 계속 보이며 충돌·소리 규칙은 유지한다. 최종 DX12의 접촉·당김 장면을 직접 확인했다.

## 해석과 남은 범위

자동화의 목표 상태 도달과 수동 연속 완주를 구분한다. Stage3 목표 검사는 적 이동을 관측한 후 적 tick/충돌을 테스트 프로세스에서 격리하고 플레이어 위치를 준비한다. 원본 맵에는 격리 설정을 저장하지 않는다. 따라서 이것만으로 적을 회피하며 모든 방을 연속 완주한 난이도 검증을 주장하지 않는다.

제한시간 600/900/1200초, Stage3 바구니 부재에 따른 표식 회복, 방울 사용의 필수성·적 밀도는 조정 여지가 있다. 별도 엔딩 시네마틱, 패키징한 Shipping 빌드의 실행, 모든 하드웨어의 성능·모든 가능한 입력 조합을 검증했다는 뜻은 아니다.

최종 DX12/RTX 4060 Laptop/1280×720 기본 멀티스레드 PIE의 시작 구역 6초 관측은 313프레임, 평균 19.18ms·95백분위 17.92ms였다. 최초 PSO 준비의 긴 프레임이 평균에 포함된다. 이는 짧은 구역 관측이며 전체 맵·패키지 벤치마크나 60fps 보장이 아니다. 이전 단일 스레드 진단 실행의 수치는 기본 실행 성능으로 사용하지 않는다.

자동화의 경고 10건은 빈 테스트 월드의 Settings/viewport/눈 본 누락 또는 의도적으로 만든 실패 경로를 포함한다. 실패 수와 구분하여 `AutomationSummary.json`에 원문을 보존한다. 여러 검사 프로세스가 기본 MCP 포트를 공유할 때 발생한 포트 바인딩 오류는 검사 기능에 사용하지 않은 서버의 충돌이며 실제 플레이 실패로 분류하지 않는다.

상호작용 중 다른 애니메이션이 소유권을 가져가는 강제 테스트에서 발생하는 Animation Blueprint 모드 경고, tick을 멈춘 적에게 소리가 도달해 발생하는 회전 재생 대체 경고는 해당 fixture의 조건과 함께 해석한다. 엔진 초기화 전 `UE::UnifiedErrorTest` 오류 표시는 엔진 Core 테스트의 자체 진단 출력이며 Catrun 테스트 결과의 실패 수가 아니다.
