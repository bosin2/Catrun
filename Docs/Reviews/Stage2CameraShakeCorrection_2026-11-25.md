# Stage2 실제 카메라 진동 보완

2026-11-25. 기존 철창 연출은 미세한 후처리 UV 이동뿐이라 눈에 잘 띄지 않았다. 이번에는 PlayerCameraManager의 실제 카메라 진동을 연결했다.

- 철창 하강: 카메라 로컬 좌우 0.8cm·상하 1.2cm, 11/15Hz. 하강 구간 동안만 약하게 유지한다.
- 철창 착지: 좌우 3cm·상하 4cm, 9/13Hz, 0.38초. 짧은 충격 후 부드럽게 사라진다.
- 해당 연출이 만든 진동 인스턴스만 중지하고, 종료·초기화·중단 시 참조를 정리한다. 카메라 이동 경로·회전·화각·먼지·퍼즐 설정은 유지했다.

별도 DX12 PIE에서 A/B/C 완료와 A 초기화·director 종료 5/5, 저장된 프로젝트를 다시 연 뒤 A 완료 1/1 통과했다. 카메라 설정값 대신 최종 PlayerCameraManager 시점과 기준 CameraComponent의 차이를 측정했다. 하강 좌우 왕복 약 1.6cm·상하 약 2.4cm, 착지에는 더 큰 진동을 확인했고 종료 후 측정 변위는 0이었다. 입력 복귀도 확인했다. 내부 보호된 ActiveShakes 배열은 Python에서 읽을 수 없어 레지스트리 전체 비어 있음이나 풀에 남은 UObject의 finished 상태를 주장하지 않는다.

새 진동 패턴은 Blueprint CDO 설정 후 컴파일하여 런타임 인스턴스에 패턴이 전달되는지 확인했다. 초기 설정만 저장하면 런타임 패턴이 None이 되는 문제가 있었으며 재컴파일과 새 인스턴스 생성·콜드 로드 검사로 수정했다.

원본 에디터에서 파일을 사용 중이어서 새 진동 에셋 두 개만 복사하고 기존 BP_StatuePresentation에는 동일한 그래프 변경을 에디터 내부에서 적용·컴파일·저장했다. 검증본과 노드·핀·값·연결이 일치한다. 비교에서 제외한 차이는 한글/영문 UI의 타입 라벨과 Scale 1.0/1.000000 표기뿐이다. 현재 열린 에디터에 적용돼 재시작이 필요 없다. 두 맵과 먼지·레터박스 재질은 작업 시작 해시를 보존했다.
