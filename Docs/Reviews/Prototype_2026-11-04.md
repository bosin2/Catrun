원인은 원래 클립 유실이 아니라 `BP_TutorialIntro`의 실제 플레이어 고양이 바인딩 누락이었다. 재생 전에 고양이와 시작·기상 카메라의 possessable 바인딩을 연결했다. 원래 시퀀스·클립·8개 컷과 spawnable 카메라는 보존했다.

## 갑옷·고양이·촛불과 바구니

C++는 감지 우선순위·경로·충돌·잡기 단계·카메라와 입력 소유권을 담당하고 BP/AnimBP는 애니메이션과 연출을 담당한다. 가까운 고양이 감지가 소리·표식 추적보다 우선하며 촛불 감지에는 시야 차단을 적용했다. 고양이·갑옷·촛불 캡슐은 Pawn을 상호 차단한다. 모든 실제 동선·문 애니메이션 조합까지 검증했다는 뜻은 아니다.

바구니는 진입·탈출 중 새 장애물, 중단, 안전한 위치 복구와 숨김 상태의 일관성을 보완했다. 기존의 매 프레임 작업 방지와 제한된 빈도의 조회를 유지했으며 측정하지 않은 성능 향상률은 주장하지 않는다. 튜토리얼과 Stage1 연회장 대표 바구니는 API로 충돌 없는 접근점까지 배치한 뒤 실제 F 입력으로 진입·숨기·탈출했다. 최종 충돌·걷기·원래 AnimBP와 각각 카메라 폭900/1035 복구를 확인했다. Stage1 첫 F는 에디터 뷰포트 포커스가 없어 전달되지 않았고, 화면 클릭 후 F로 검증했다. 창고26의 정면 한 지점은 장애물과 겹쳐 배치를 거부했으며 다른 접근 경로를 추가 검사 중이다.

추가 검사에서 창고26도 남동쪽315도 접근점에서 실제 F 진입·탈출을 통과했다. `Task5/BasketStorage01`이 근거이며 바구니 배치를 수정하지 않았다. `OccupiedDoor01`은 촛불을 문 종료 위치 가까이 배치한 유효한 충돌 검사로, 초기 간격3cm·표본 최소0.039cm·문 종료 간격0.323cm를 유지했다. `ArmorPair01`은 갑옷끼리 최소0.0648cm 간격으로 막힌 뒤 제한 시간 안에 탐색·원래 자리 복귀를 확인했다. 두 경우 목적지에는 도달하지 못했으므로 동적 캐릭터 자동 우회 기능으로 표현하지 않는다.

튜토리얼에서는 방울 유인, 문 열기, 실제 이동 입력을 통한 캣홀 통과와 침실 복귀를 확인했다. 자동 경로04가 침실 출구에서 막혀, 시작부터 계단까지 끊김 없는 실제 탈출은 아직 검증하지 못했다. 재분석 결과 그 침실 경유점은 문 중심과 정렬되어 있었고, 실제 차단 컴포넌트는 아직 확인되지 않았다. 별도로 복도 문의 액터 원점은 경첩이며 실제 통과 중심은 그보다 북쪽60cm인 Y662임을 확인했다. 이 중심을 지나는 새 경로를 준비했으며 검증 전 성공으로 처리하지 않는다. 검사 세부 사항은 `.superpowers/sdd/2026-11-04-playable-prototype/task-5-ai-integration-report.md`와 `task-5-tutorial-route-plan.md`에 있다.

- `ABP_ArmorPresentation`은 기존 최종 스켈레톤·클립을 사용한다. 일반 이동은 짧게 블렌딩하고 회전·문 애니메이션 경계에서는 네이티브 회전이 중복 적용되지 않게 처리한다. 실제 90도 회전은 약 0.5초이며 연속 180도 회전과 이동 속도 복귀를 검사했다.

## 동상과 남은 검사

동상의 네이티브와 BP 연출 구현·독립 리뷰를 통과했다. 가속·감속 밀기,80% 접촉 후 정확한 정착, 붉은 눈, 검은 띠, 문 카메라, 바닥 먼지·진동, 아래로 완전히 내려가는 철창과 시점 복귀를 연결했다. 조작·적 정지는 소유권과 제한시간을 관리하며 BP는 눈·카메라 설정·풀링된 먼지8개를 담당한다. 사운드 파일은 추가하지 않았다.

## 직접 플레이 후 추가 요청 — 아직 미적용

사용자는 현재 직접 플레이 중이라고 확인했다. 자동 입력·맵 전환·PIE 중지·에디터 종료·빌드를 멈추고 실행 중인 세션은 그대로 두었다. 최종 수정 작업의 관찰 콜백6개는 모두 종료됐으며 마지막 소유 상태에서 경로 디버그는0, 임시 갑옷 플래그도 원래 값으로 복구했다. 사용자의 현재 미저장 상태를 새로 검사하거나 저장하지 않았다.

- 튜토리얼 갑옷을 더 뒤로, 촛불은 왼쪽부터 돌면서 시작점 가까이 위협하되 캣홀을 침범하지 않도록 조정할 계획이다. 실제 감지 반경과 방울 전달 예산을 함께 확인해야 하므로 위치만 옮기고 탈출 가능하다고 단정하지 않는다.
- 갑옷의 어색함은 원본 클립 전체의 파손보다 연결·타이밍 문제를 먼저 수정할 근거가 강하다. 선형 중단 회전 계산과 실제 비선형 root 곡선은 저장 표본에서 약17.6도 차이가 나며, 5배속 turn·전신 블렌드0·즉시 잡기 방향 변경을 확인했다. Grab2.3초는 손이 최저점에 도달하는 약3.5초보다 빠르다. 원본 1배속/5배속과 동일 구도의 게임 재생을 비교한 뒤 수정한다. 자세한 근거: `.superpowers/sdd/2026-11-04-playable-prototype/armor-motion-user-analysis.md`.
- 문 카메라는 현재0.65초 이동과1170→650 확대가 겹친다. 첫 조정안은 이동2초·복귀1.6초, 직교 화면 폭1050, 진동0.00015다. 기존 문·먼지·붉은 눈·입력 복구는 유지하며 A/B/C 실제 화면 비교 후 확정한다.

계획은 `.superpowers/sdd/2026-11-04-playable-prototype/user-playtest-adjustment-plan.md`, 작업 중 판단과 보존 사항은 `Prototype_Decisions_2026-11-04.md`에 있다. 새 요청의 수치와 배치는 아직 저장된 게임 에셋에 적용하지 않았다.

독립 리뷰는 네이티브 1–3, 인트로4a, 정식 맵4b, 애니메이션4c, 동상 연출4d까지 통과했다. 4c 관찰 스크립트가 AnimBP에 SingleNode 전용 조회를 호출해 만든 로그 경고는 진단 도구의 비차단 수정 항목이다. 기존 시작 시 SpawnActor의 null class 경고는 GM_Cat의 null HUDClass 경로가 가장 강한 후보이나 호출 스택으로 확정하지 않았다. 배치된 고양이·인트로를 보존하는 범위에서 최종 점검한다.

최종 검사에는 실제 바구니 F 입력, 출구 겹침에 의한 전환, Stage2 파동 화면, 갑옷·촛불이 막는 동선, 문 애니메이션 종료 위치의 충돌, 동상 3개와 초기화, 카메라·조작 복구가 포함된다. 문 루트 보정의 충돌 위험은 특정 시험에서 재현되지 않았으므로 아직 확인된 버그로 기재하지 않는다.

## 에디터 종료 문제와 보존

이번 작업 중 제가 실행한 에셋 작성 과정에서 에디터가 두 차례 충돌했다. 맵 복제 후 Python이 이전 월드 참조를 유지한 경우와 이미 연결된 갑옷 BP 그래프를 재구성한 경우다. 사용자의 게임 코드가 원인이라고 단정하지 않았으며 충돌 로그·백업을 보존했다.

맵 작성은 복제·저장과 이후 로드를 분리하고 참조 수명을 제한했다. 갑옷 설정은 올바른 그래프를 검증 후 재사용하도록 변경했다. 재실행한 에디터에서 설정 재사용 2회, 6개 패키지의 엄격한 컴파일·재로드, 새 잡기 재생·정리 검사를 통과했다. 작성 경로의 회피·복구 검증이며 엔진 내부 오류 자체를 수정했다는 뜻은 아니다.

이후 동상 먼지 재질 저장·편집 중 별도로 응답 정지가 발생했다. 마지막 로그는 BP를 Actor로 전달한 편집 API 형식 오류이며, 이것만으로 정지의 내부 원인을 단정하지 않는다. 저장 완료·PIE 중지 상태에서 정상 종료도 응답하지 않아 해당 프로세스만 강제 종료했다. 새 에디터에서 실제 MainMenu와 MCP·Python 연결을 확인했으며, 저장된 패키지와 연출을 다시 검증하고 있다. 기록: `Task4d/editor-hang-20261104.json`, `EditorAssets5.log`, `EditorAssets6.log`.

MCP는 실행 중인 UE5.8 프로젝트의 실제 현재 맵 조회로 확인했다. 최종 작업이 끝나면 요청대로 저장 상태를 확인하고 언리얼을 정상 종료한다. 오디오 파일은 나중에 삽입하도록 남겨 두며 Stage3·각성 시스템·원격 배포는 제외한다.

RT 지오메트리 경고는 별도 조사 중이다. 확인한 튜토리얼 108.146MB는 400MiB 풀의 경고 기준 20%를 넘은 것으로 전체 GPU 메모리 고갈의 증거가 아니다. Stage2의 신뢰할 수 있는 측정은 아직 없다. 경고 숨김을 최적화로 처리하지 않는다.
