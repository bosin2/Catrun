# 갑옷 붙잡기와 애니메이션 연결

2026-11-04 Task4c 연결 및 실행 검증 기록. 네이티브 기반에 BP/AnimBP 연출을 연결하고 실제 PIE 재생, 취소, 저장 후 재로드를 확인했다. 독립 최종 리뷰는 메인 작업에서 진행한다.

## 확인한 문제와 분리 방식

갑옷의 추적·문 열기·붙잡기 판단은 `ACatrunArmor`에 남기고, 붙잡기 카메라·고양이 들어 올리기·취소 복구는 `UCatrunCapturePresentationComponent`로 분리했다. 연출은 Framing → Pickup → Holding → Fading 단계를 사용한다. BP에는 단계와 SessionId를 전달하고, 잡기·종료 알림은 같은 세션일 때만 처리한다. 초기 시작 콜백 안에서 즉시 재시작하는 경우는 거절하여 갑옷 상태와 고양이 제어가 엇갈리지 않게 했다.

카메라는 두 캐릭터를 함께 볼 수 있는 여러 방향을 검사하고, 벽과의 구체 충돌 검사 및 두 피사체에 대한 시야 검사를 사용한다. 전환 경로도 검사한다. Stage1 방과 좁은 출입구, Stage2 책장 옆에서 두 캐릭터가 보이는 실제 캡처 화면을 확인했다. 이는 모든 벽 배치의 화면 품질을 보증하지 않는다. 손 지지와 허리 간격을 보는 별도 측면 관찰 카메라는 네이티브 카메라 검증과 구분해 기록했다.

취소 시 입력·카메라·이동·충돌·애니메이션 상태는 해당 연출이 소유한 부분만 돌려놓는다. 복귀 지점이 막혔으면 같은 층의 가까운 위치를 실제 캡슐과 바닥·이동 경로로 검사한다. 안전한 위치를 입증할 수 없으면 기존 스테이지 재시작 경로로 복구한다. 바구니의 복귀도 같은 안전 검사 원칙을 사용한다.

## 실제 에셋 연결 상태

작업 전 갑옷은 Final 메시를 AnimBP 없이 SingleNode로 재생했으며, 두 Blueprint 재생 플래그는 false, 고양이 픽업 클립은 null이었다. 현재 갑옷은 `ABP_ArmorPresentation`의 DefaultSlot을 사용하며, `BP_LivingArmor.AnimationRequested`가 네이티브의 클립·반복·재생률을 받는다. 두 플래그는 각 소비자가 연결된 상태에서 true다. 선택적인 null 요청은 포즈를 바꾸지 않는다.

`OnPhaseChanged`는 BeginPlay에서 한 번 바인딩한다. Pickup마다 새 `BP_CapturePlayback`이 원래 SessionId를 보관하고 갑옷 몽타주와 고양이 SingleNode 클립을 재생한다. 몽타주 인스턴스와 원래 세션이 일치하는 알림만 처리한다. 취소 시 소유한 몽타주만 멈추며, 네이티브가 복원한 AnimBP를 덮어쓰지 않는다. 0.1초 간격 수명 검사는 소유 컴포넌트 삭제·세션 변경·캡처 종료 시 남은 컨텍스트를 정리한다. 고정 15초 만료는 없으며, 재생률 0.25에서 16초 이상 유지한 뒤 취소하는 실행 검사를 통과했다.

고양이의 기존 `ABP_Cat_Final`과 이동 Blendspace는 그대로다. 새 `AN_BlackCat_CaughtHeld`는 기존 Final 스켈레톤의 8초 Idle을 복제하여 몸·다리·꼬리 20개 트랙의 회전을 변경했다. 241개 키 전체에서 원래 위치·크기와 수정하지 않은 루트·얼굴 등의 회전 보존을 검사했다. 붙잡기 종료와 취소 후 원래 `ABP_Cat_Final_C`로 돌아온다.

기존 갑옷 `hand_l`·`hand_r` 본은 실제로 존재한다. 원본 픽업 7초와 회전 2.5초 클립은 변경하지 않았다. 회전 재생률 5에서 완료된 90도 회전은 게임 시간 0.5000~0.5019초였고, 완료 경계의 월드 루트 각도 차이는 0.073도 이하였다. 같은 클립 두 번으로 180도를 돌고 이동 재생률 1로 복귀한다. 고양이 Final 메시의 배율 2, yaw -90도, Z -24 조합을 유지하며 손 보정값은 `(8,0,15)`로 조정했다.

`AM_ArmorPickupPresentation`의 잡기 알림은 2.3초, 종료 알림은 6.85초다. 들어 올릴 때 재현된 고양이 yaw 90도 순간 변경은 승인된 네이티브 수정으로 실제 잡기 시작 각도에서 최단 경로로 보간한다. 위치와 같은 기존 0.3초 SmoothStep을 사용한다. 새 세션·179/-179도 경계·중간/끝 각도·0초 즉시 완료 검사를 포함한 네이티브 10개 회귀 검사가 통과했고, 재빌드 후 실제 재생에서 중간 각도를 확인했다.

## 에셋 작업 기준

- 갑옷 AnimBP는 네이티브에서 받은 애니메이션·반복·재생률을 표현하고, AI 판단을 복제하지 않는다.
- 붙잡기 BP는 받은 세션으로 잡기·종료를 알리며, 취소된 재생의 알림을 새 세션에 재사용하지 않는다.
- 고양이는 실제로 들어 올려져 매달리는 자세를 재생한다. 전용 클립이 없으면 기존 Final 스켈레톤에 제작하고, 외형·비율·리그를 유지한다. 이름이 비슷한 레거시 클립을 바로 연결하지 않는다.
- 고양이 액터 위치는 네이티브가 손 중간 지점으로 이동시킨다. BP가 다시 부착하거나 액터를 움직여 이중 이동을 만들지 않는다.
- `bUseBlueprintAnimation`과 `bUseBlueprintPresentation`은 서로 다른 옵션이다. 현재 양쪽 BP 소비자가 연결된 상태에서 켜져 있다. 알림을 의도적으로 누락한 실행에서도 네이티브 제한 시간 복구가 잡기·종료를 처리했다.

조정 위치는 `PrototypeTuning.md`에 정리했다. Task4c의 구체적인 재생 근거·제한·반복 실행 진입점은 `.superpowers/sdd/2026-11-04-playable-prototype/task-4c-report.md`와 `Saved/Prototype20261104/Task4c`에 있다. 문 이동의 기존 비스윕 보정은 변경하지 않았으며, 검사한 문 중단 사례의 Framing/Pickup에서는 캡슐 간격 약 6cm를 유지했다. 모든 경로의 충돌 안전성을 입증한 결과는 아니다.
