# Catrun C++·BP 역할 및 튜닝 정리 계획

2026-11-03 · 구현 전 설계 제안. 현재 점검 기준 로컬 HEAD `0f1800a`. 목표는 튜토리얼과 스테이지 1·2·3 완성이다. 스테이지 2의 동상·발판 시스템은 유지한다. 장치 교체 논의는 스테이지 3의 성문 장치에만 해당하며 대체안은 미정이다. 각성도는 후순위다. 이 문서 작성으로 코드·에셋의 역할 분리가 완료된 것은 아니다.

## 1. 역할 기준

외부 자료는 [OpenSourceDependencies.md](OpenSourceDependencies.md)에 정한 두 개만 사용한다. ActionRoguelike의 `RogueAction`과 `RogueActionComponent`에서 판정·상태·연출 함수 분리 및 시작·종료 이벤트 구조를 참고한다. 기존 컴포넌트 안에서 필요한 부분부터 적용한다.

**C++는 반복 사용되는 판정·상태·계산을 소유하고, BP는 콘텐츠 조립·배치·연출을 담당한다. 튜닝값은 DataAsset 등 지정된 데이터 한 곳에서 읽는다.** 모든 BP를 C++로 옮기거나 기존 연출 코드를 한 번에 재작성하지 않는다.

| 기능 | C++ 담당 제안 | BP·AnimBP·레벨 담당 제안 |
| --- | --- | --- |
| 고양이 이동 | 이동 가능 상태·속도 선택·공통 상태 조회 | 입력 연결, 이동 애니메이션, 메시·카메라 구성 |
| 방울 | 사용 가능 판정, 금지 구역·은신·행동 중 여부, 쿨다운, 실제 소리 이벤트 1회 발생 | 사용 요청, 몽타주·효과음·이펙트, 발생 타이밍 알림, 불가 안내 UI |
| 갑옷 | 감지·소리·표식의 선택, 목표 좌표, 경로·속도, 상태 전환·복귀 | 메시·애니메이션·효과음·포획 카메라 설정, 순찰 지점 배치 |
| 소리 | 전파·감쇠·도달·청각 이벤트, 실제 계산 결과 제공 | 파동 머티리얼·표시 시간·색·청각용 효과음 |
| 촛불·표식 | 시야 판정·표식 생명주기·추적 갑옷 선정 | 이동 경로 배치, 외형·시야 표시·표식 효과 |
| 바구니·문·캣홀 | 상호작용 허용·이동 안전·충돌·표식 해제 시점 | 진입·퇴장·개폐 연출, 방향·금지 구역·배치 설정 |
| 스테이지·튜토리얼 | 여러 맵에서 재사용하는 완료·실패·초기화 판정이 필요할 때 공통화 | 각 맵 목표 연결, 설명·트리거·레벨 전환 연출 |
| UI·카메라 | 표시할 상태와 이벤트 제공 | UMG, 화면 구성, 안내·페이드·연출 |

분리 기준은 파일 확장자가 아니라 **동일 상태를 두 곳에서 결정하지 않는 것**이다. BP가 입력을 받더라도 최종 방울 사용 판정은 공통 C++ 함수 한 곳에 둔다. 몽타주 알림은 소리 발생을 요청하고, C++가 현재 행동과 중복 발생 여부를 검증한다. 취소·포획·재시작 시 행동과 타이머가 남지 않도록 한다.

이미 안정적으로 동작하는 C++의 위치 계산·바구니 궤적·문 상호작용은 유지한다. 연출 교체가 필요한 부분부터 이벤트와 설정을 노출한다. 스테이지 3 장치가 미정인 상태에서 범용 퍼즐 프레임워크를 선행 제작하지 않는다.

## 3. 튜닝값의 단일 출처

우선 기존 `DA_SoundSettings`와 소비 코드를 기준으로 정리하고, 동일한 수치가 BP 상수·C++ 설정·액터 인스턴스에 중복된 곳을 제거한다. 아래는 논리적 분류이며 새 에셋 이름·개수를 확정한 것이 아니다.

| 범주 | 관리 값 | 주의점 |
| --- | --- | --- |
| 고양이 | 살금살금·걷기·달리기 속도, 방울 쿨다운 | 입력 경로·UI가 같은 기준을 읽음 |
| 소리 | 크기별 전파 예산, 전달 속도, 재질 감쇠, 발소리 간격 | 실제 청각과 표시용 확장 수치의 의미 구분 |
| 갑옷 | 순찰·표식·방울·발소리 속도, 감지 거리, 반응·조사·재탐색 시간 | 우선순위 전환으로 속도가 의도치 않게 변경되지 않는지 확인 |
| 촛불·표식 | 시야·회전, 추적 담당 수와 교체 조건 | 담당 수·선정 규칙부터 확정 |
| 연출 | 파동 색·지속, 포획 카메라·몽타주 | 게임 판정값과 구분해 편집 |
| 레벨별 설정 | 순찰 경로, 문·바구니 방향, 캣홀 방울 금지 범위 | 공간 배치는 각 레벨이 소유; 공통 기본값과 의도적 예외만 구분 |

통합의 완료 기준: 값을 한 번 바꾸면 모든 관련 실행 경로에 반영되고, 예외값의 위치가 명확하며, 이전 상수가 뒤에서 적용되지 않는다. 첫 이전 단계에서는 기존 실효 수치를 보존하고 밸런스 변경은 별도로 진행한다. 애니메이션 발생 시점은 가능하면 애니메이션 알림에 연결하며 같은 타이밍을 여러 타이머에 복제하지 않는다.

## 4. 갑옷 우선순위에서 남은 결정

- 사용자 확정: **근처 감지 > 소리 > 표식**.
- 사용자 추가 지적: 표식은 고양이 객체에 붙으므로 발소리가 표식보다 우선할 의미가 있는지 의문.
- 추천 세부안: **근처 감지 > 방울 조사 > 표식 추적 > 발소리 조사**. 발소리는 과거 좌표이고 표식은 실시간 좌표다. 방울만 의도적 유인 행동으로 별도 취급한다. 아직 채택이 확정되지 않았다.
- 연계 제안: 방울 조사 중 표식 유지, 조사 이동·돌아보기 종료 후 유효한 표식 추적 재개. 조사 중 바구니에서 표식이 지워지면 재개하지 않는다.
- 소리 조사 좌표는 발생 당시 위치여야 한다. 방울을 들었다는 이유로 고양이를 실시간 추적하면 유인 행동이 성립하지 않는다.
- 표식 재탐색 타이머가 매번 소리 목표를 덮어쓰지 않도록 해야 한다. 포획·문 열기·회전 등 실행 중 행동의 중단 가능 시점도 함께 정한다.

## 5. 실행 순서와 검증 기준

1. 갑옷의 소리 종류별 우선순위·조사 종료·표식 재개를 확정한다. 튜닝 목록과 현재 참조 경로 정리는 병행 가능하다.
2. 방울 판정과 쿨다운을 한 곳으로 연결하고 BP 상수 중복을 제거한다. 일반 입력·대체 입력·금지 구역·은신·연속 입력·행동 취소에서 같은 결과인지 검사한다.
3. 고양이와 적의 튜닝 참조를 통합하고 타입 기반 상태 조회로 연결한다. 이동 속도·행동 중 상태·바구니 출입의 기존 동작을 확인한다.
4. 확정된 갑옷 규칙을 반영한다. 근처 감지의 우선, 소리 위치 고정, 표식 중단·재개·해제, 접근 불가 목표와 문 통과를 검증한다.
5. 튜토리얼→1→2→3의 완료·실패·재시작을 연결한다. 스테이지 2는 기존 동상·발판 시스템을 유지하고 밀기·작동·문 개방을 검증한다. 스테이지 3 장치는 결정 후 제작하며 전체 연결은 각성도에 의존하지 않는다.

개발자 2명 분업 제안: 한 명은 공통 C++·튜닝 연결, 다른 한 명은 레벨·BP 연출·튜토리얼·전환을 맡는다. 공통 함수·이벤트 이름과 수정 에셋을 먼저 합의한다. 실제 담당자는 별도 확정하며 다른 팀원 역할은 역량 확인 전 배정하지 않는다. 빌드·BP 컴파일과 함께 실제 입력 플레이를 확인해야 하며 컴파일 성공만으로 상호작용 완료를 판정하지 않는다.
