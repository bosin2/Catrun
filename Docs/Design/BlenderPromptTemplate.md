# Blender 작업용 복사 지시문

사용법: 공통 지시문과 에셋 명세를 함께 전달한다. `[ ]`는 실제 요구로 채운다. 기존 원본을 수정할 때는 일반 권장값보다 보존 규격을 우선한다. 자세한 근거는 [디자인 지침서](BlenderDesignGuide.md)에 있다.

## 공통 지시문

```text
Catrun 《마왕님, 고양이가 도망갑니다》에 사용할 게임용 에셋을 Blender로 작업해줘.

먼저 지정한 기존 에셋과 현재 Blender 파일의 오브젝트·재질·UV·단위·축·원점·리그를 읽어라. 기존 모델, 재질, 리그, 다른 에셋을 임의로 다시 만들거나 교체하지 마라. 이는 기존 파일을 보존하라는 뜻이다.

신규 제작 요청이면 이번 용도와 구역에 맞춰 새로 만들어라. 기존 에셋을 복제하거나, 다른 구역의 에셋을 색만 바꾸거나, 크기를 늘리거나, 부품을 떼어 붙여 대신하지 마라. 단, 같은 벽·바닥 타일의 반복 배치와 갑옷·촛불의 스테이지별 재질 변형은 허용한다. 기준작은 치수·재질·문양·디테일 밀도를 맞추는 비교 대상으로만 써라. 새 파일은 날짜가 붙은 새 폴더에 저장해라.

원본 기준 위치는 C:/Users/whghk/Desktop/CastleKit이다. 대상 파일에 접근할 수 없으면 확인한 척하거나 다른 버전을 임의로 대체하지 말고 그 사실을 알려라.

디자인 방향은 “귀여운 검은 고양이가 오래되었지만 생활의 흔적이 남은 묵직한 고딕 성을 밤에 탈출하는 분위기”다. 캐릭터는 형태와 표정이 쉽게 읽혀야 하고, 배경은 단정한 구조에 설득력 있는 목재·돌·직물·금속 재질을 사용한다. 큰 덩어리 → 구조 → 작은 재질 디테일 순서로 읽히게 해라.

튜토리얼·Stage1 생활 공간은 어두운 월넛, 버건디, 회갈색 돌, 바랜 황동, 크림색 천을 기준으로 한다. Stage2는 약한 푸른 기의 회색 절단석, 벽보다 밝은 회색 판석, 흑철, 남청 직물, 작은 황동 인레이와 제한된 마도 문양을 기준으로 한다. Stage2 Backups 안의 옛 에메랄드 버전을 기준으로 삼지 마라. 보라·라일락은 Stage2의 조명, 작은 장식과 발광에만 쓰고 벽·바닥 석재 고유색으로 칠하지 마라.

Stage2→3 승강기는 목재 판재, 흑철 보강, 밧줄·도르래와 회색 절단석을 기준으로 한다. Stage3은 고딕 군사 경비시설이다. 세로 분할된 회갈색 석벽, 다발 기둥, 팔각석 바닥, 무광 흑철, 버건디 군기를 기준으로 하고 황동은 작은 접합부에만 쓴다. 왕실·성당·종교 설정, 스팀펑크, 녹색 군기, 전면 금색 테두리를 넣지 말고 Stage1의 넓은 붉은 러그와 Stage2의 푸른 룬·남청 러너를 반복하지 마라. Stage3 Sample01과 반려된 Puzzles/SM_S3_GuardianStatue는 기준으로 삼지 마라.

고딕 형태는 아치·세로 패널·몰딩·문양으로 표현한다. 기능과 구조가 보이는 실루엣, 얕은 베벨, 부재 방향에 맞는 목재 결, 낮은 대비의 석재 입자, 직조와 제한된 주름을 사용해라. 접촉 위치를 따른 마모를 넣고, 전 표면의 과한 노이즈·녹·흰 긁힘, 플라스틱 같은 반사, 과도한 스파이크·해골·고어 장식을 추가하지 마라. 기존 가고일의 뿔·날개·발톱 같은 정체성은 보존한다.

고양이 관련 작업은 기존 검은 몸, 큰 초록 눈, 붉은 목걸이, 황동 방울, 얼굴·몸 비율·크기·리그를 보존한다. 귀여움은 귀·꼬리·깜빡임과 자연스러운 카툰 타이밍으로 표현한다. 사실적인 고양이로 재디자인하거나 얼굴·몸을 과도하게 변형하지 마라. 배경 가구와 가고일까지 귀엽게 둥글리는 것은 금지한다.

BaseColor에는 조명·그림자·Bloom을 고정해서 그리지 마라. 실제 황동·강철과 천에 그려진 금색 문양을 구분해라. 발광은 필요한 부위의 마스크 또는 분리된 메시로 제어하며, 원본의 기본 강도가 0이면 유지한다.

아래 에셋 명세의 실제 cm 치수, X/Y/Z, 정면, 원점, 가동 공간, 부품 분리를 지켜라. 바닥 중앙 원점을 모든 물건에 강제하지 마라. 기존 문 경첩, 모듈 모서리, 벽 부착 기준점, 조립 위치를 유지한다. 새 정적 메시의 기본 목표는 Rotation 0, Scale 1이다. 기존 리그에 무조건 Apply Transform을 실행하거나 Unreal용 배율을 이중 적용하지 마라.

UV0와 필요한 BaseColor / Normal_DX / ORM을 제공한다. BaseColor는 sRGB, Normal_DX·ORM·마스크는 Non-Color, ORM은 R=AO/G=Roughness/B=Metallic이다. DX 노멀의 Blender 표시용 G 변환과 Unreal용 원본을 구분한다. UV1·LOD·텍스처 해상도·재질 슬롯은 이번 에셋 조건에 맞춰 정하고, 기준작의 고해상도를 무조건 복제하지 마라. 텍스처 가로·세로는 2의 거듭제곱을 기본으로 하고 최소한 4의 배수로 맞춘다. 상대 텍스처 경로와 전달용 패킹을 확인한다.

필요한 단순 충돌만 만들고 이름을 UCX_<MeshName>_00 규칙에 맞춘다. 통로·문틀·가동 공간을 충돌로 막지 마라. 메시·부품·충돌 구조에 맞춰 FBX를 내보낸 뒤 별도 임시 장면에서 재임포트하여 치수·축·원점·스케일·조립 상태와 파일 연결을 검사해라. 리그 작업이면 기존 스켈레톤과 액션 호환성도 확인해라.

납품은 이번 에셋의 .blend, 필요한 .fbx, Textures 폴더, 짧은 작업 결과다. 기존 파일은 보존하고 지정된 범위에서만 작업한다. 미리보기 이미지·렌더·영상·HTML·카메라·조명·전시용 바닥·전시 장면은 만들지 마라.

작업 결과에는 실제 치수·축·원점·변환, 메시/재질/UV/텍스처/충돌 구성, 수행한 검사와 실패·미확인 항목을 적어라. Blender 노드가 FBX로 Unreal에 그대로 옮겨진다고 가정하지 마라. 게임의 소리·시야·상호작용·발광 연출·문 작동·배치·성능은 실제 엔진 검증을 하지 않았다면 미확인으로 남겨라. 맵 구조와 다른 에셋을 변경하지 마라.
```

## 이번 에셋 명세

```text
[이번 작업]
- 작업 종류: [신규 제작 / 지정 원본 수정 / 기존 외형 유지 애니메이션]
- 에셋 이름: [정확한 SM_ 또는 SK_ 이름]
- 용도와 구역: [튜토리얼 / Stage1 / Stage2 / Stage2→3 승강기 / Stage3, 장식·장애물·통로·상호작용 등]
- 결과를 저장할 폴더: [절대 경로]
- 수정 대상 원본: [정확한 파일 경로 또는 신규]
- 형태 기준작(비교용, 메시 복제 금지): [정확한 파일 경로와 맞출 특징]
- 재질 기준작(비교용): [정확한 파일 경로와 맞출 특징]

[크기와 구조]
- 메시 종류: [Static / Skeletal]
- 전체 치수: X [ ] × Y [ ] × Z [ ] cm
- 정면과 위쪽: [예: 정면 -Y, 위 +Z]
- 원점: [바닥 중앙 / 모듈 모서리 / 경첩 / 벽 부착 기준점]
- 부품: [이름별 목록, 고정/이동/변형 여부]
- 통로·개구부·가동 범위: [실제 수치와 축 또는 해당 없음]
- 반드시 보존할 요소: [외형·치수·리그·재질·원점 등]
- 이번에 바꿀 요소: [대상과 변경 범위]

[표현]
- 주재질 / 보조재질 / 포인트: [ ]
- 장식 문양과 위치: [ ]
- 마모 위치와 정도: [ ]
- 발광 영역과 기본 상태: [없음 / 지정 영역, 기본 강도]
- 추가로 금지할 것: [ ]

[기술 및 납품]
- 배치 빈도·주로 보이는 거리: [ ]
- 메시/텍스처 예산: [지정값 또는 원본을 읽고 합리적인 예산을 제안]
- UV1·LOD 필요 여부: [기존 파이프라인 기준 / 지정값]
- 충돌: [없음 / 부품별 용도와 반드시 비울 공간]
- 리그·액션·루프·Root 기준: [Skeletal일 때만]
- 파일명·덮어쓰기 허용 범위: [ ]
- 이번에 확인할 항목: [ ]
```

임의의 전역 설정으로 축을 통일하지 않는다. 대표적으로 Stage2 양면 책장은 ±X 개방·±Y 폐쇄, 가고일은 바닥 중앙 원점, 누름판은 주변 바닥 높이에 공통 원점, 문짝은 각 경첩 원점이다. 서로 다른 에셋의 기준을 섞지 않는다.
