## 0. 게임 개요와 범위

| 항목 | 현행 기획 |
|---|---|
| 제목 | 마왕님, 고양이가 도망갑니다 / 프로젝트 Catrun |
| 장르 | 고정 각도 쿼터뷰 잠입·유인·환경 퍼즐 |
| 플레이 | 고양이 한 마리를 조작하는 싱글플레이 |
| 개발 환경 | Unreal Engine 5.8 계열, C++·Blueprint·UMG |
| 확인된 실행 대상 | Windows 개발 환경. 최종 배포 플랫폼·최소 사양은 미정 |
| 현재 플레이 구간 | 메인메뉴 → 튜토리얼 → 스테이지 1 → 스테이지 2 → 스테이지 3 |
| 후속 목표 | 전용 엔딩 연출, 전체 연속 완주에 따른 난이도 조정. Stage3 목표·맵·출구는 구현 |
| 개발 일정·담당 | 이 문서로 새로 지정하지 않음. 팀회의에서 담당·마감 확정 |

마왕은 마음에 든 고양이를 성에 데려왔다. 고양이는 원래 집으로 돌아가려 한다. 하수인들은 마왕의 고양이가 성 밖으로 나가지 못하게 막는다. **방울 때문에 들키는 고양이가 그 방울로 갑옷을 속인다.**

핵심 경험은 관찰 → 자기 위치에서 소리로 유인 → 열린 경로로 우회 → 목표 수행이다. 들키면 캣홀로 거리를 벌리고 바구니로 표식을 해제한다. 동상 밀기·발판·문·바구니 상호작용도 플레이어의 개입 수단이다. 따라서 옛 문장의 “세계에 개입하는 방법은 소리뿐”은 폐기하고 **갑옷을 의도적으로 유인하는 핵심 수단이 소리**라고 정리한다.

방울 없이 스테이지 전체를 쉽게 통과할 수 있으면 핵심 유인 경험이 성립하는지 재검토한다. 촛불만 있는 개별 구간에 방울 사용을 강제하지 않는다. “모든 스테이지의 모든 클리어 경로에서 반드시 방울이 필요”한지에 대한 검증은 아직 완료되지 않았다.

## 1. 플레이어 조작과 이동

| 조작 | 기본 키 | 행동·규칙 |
|---|---|---|
| 이동 | W/S/A/D | 바닥을 따라 이동 |
| 달리기 | Left Shift | 스태미나가 허용하는 동안 빠르게 이동 |
| 살금살금 | Left Control | 가장 느린 무소음 이동 |
| 방울 | Space | 제자리 행동, 큰 소리로 유인 |
| 상호작용 | F | 접근 가능한 바구니 진입·탈출 |
| 지도 확대 | Tab 유지 | 우상단 미니맵을 확대, 놓으면 복귀 |
| 설정 | Esc, 일부 경로 P | 공통 설정·일시정지. 에디터 Esc의 PIE 종료와 구분 |

이동·달리기·살금살금·방울·상호작용 8개 키 항목은 설정에서 재지정한다. 중복 키·조합 키·Esc 지정은 허용하지 않는다. 일반 플레이의 R 즉시 재시작은 제공하지 않는다. 자유 점프·등반은 기본 능력이 아니며, 통로·연출에서 사용하는 이동과 구분한다.

| 이동 | 현행 값 | 게임플레이 소리 |
|---|---:|---|
| 살금살금 | 53cm/s | 없음 |
| 걷기 | 79cm/s | 小 |
| 달리기 | 134cm/s | 中, 실제 달리기 상태에 맞춘 발소리 주기 |
| 갑옷 순찰·복귀 | 배치 액터 150cm/s | 다른 갑옷을 유인하는 플레이어 소리와 구분 |
| 갑옷 발소리 조사 | 공유 설정 200cm/s | — |
| 갑옷 방울 조사 | 공유 설정 250cm/s | — |
| 갑옷 표식 추적 | 공유 설정 300cm/s | — |

53·79·134는 최신 저장된 BP 그래프 확인값이다. 갑옷 수치는 실제 로드한 액터·DataAsset 기준이다. 현재 관계는 **살금살금 < 걷기 < 고양이 달리기 < 갑옷 순찰 < 갑옷 조사·추적**이다. 이전 기획의 “순찰보다 달리기가 빠르다”는 현재 상태와 다르다. 최신 요구가 적 속도 유지를 명시하므로 수치를 임의 조정하지 않는다. 이 관계의 난이도 영향은 회의 안건 M01이다.

최신 확정 요구에 따른 추가 시스템이다. 체력·HP 시스템과 혼동하지 않는다. 포획은 여전히 실패 조건이다.

| 항목 | 요구·초기 조정값 |
|---|---|
| 최대량 | 100 |
| 소모 | 실제 자발적인 지상 달리기 중 초당 20 |
| 회복 시작 | 소모하지 않은 상태가 1초 지속된 뒤 |
| 회복 속도 | 초당 25 |
| 고갈 | 걷기로 전환 |

| 비소모 상황 | 제자리 Shift, 벽에 막힌 이동, 강제 이동·루트 모션·시네마틱·정지된 게임플레이 |

UI는 `CatrunSprintComponent`의 실제 상태를 읽는다. UI 전용 스태미나를 따로 계산하지 않는다. 달리기 속도를 124→134로 한 번만 올리며 걷기·살금살금·적·시네마틱·동상 밀기 속도는 유지한다. 새 이동 조건에서의 퍼즐·도주 동선 측정은 남은 검증이다.

## 3. 방울

방울은 원거리 지점을 지정하는 기술이 아니다. 고양이가 직접 소리를 낼 위치에 간 뒤, 그 위치를 노출하고 빠져나오는 행동이다.

- 큰 소리 大, 기본 쿨다운 5초.
- 현재 저장된 행동은 소리 발생 지연 약 0.566667초, 행동 길이 1초를 사용한다. 옛 문서의 2.8초는 현행 값이 아니다.
- 바구니 안·진입/탈출 등 행동 중·공중·캣홀 금지 영역·시네마틱/전환 중에는 사용할 수 없다.
- 캣홀 주변 금지 영역은 **입력 시점과 지연 소리 발생 시점 모두 검사**한다. 원문의 “캣홀에서 방울 사용 가능”은 폐기된 규칙이다.
- 금지 영역 안내 문구는 `방울을 울릴 수 없습니다`다. 새 상태 UI는 은신 중/행동 중/공중/캣홀 안/연출 중/충전 중을 구분한다.
- 기존 `BP_CatActions`가 승인한 `LastBellTime`과 동일한 쿨다운 값을 UI가 읽는다. 별도 UI 시계를 만들지 않는다.
- 조사 중인 갑옷은 같은 크기의 두 번째 방울에 목적지를 바꾸지 않는다. 돌아보기 중에는 작은 소리에도 반응한다.

플레이어 방울 전파 예산은 튜토리얼과 스테이지 1·2·3 모두 500cm다(2026-11-26 사용자 지시로 튜토리얼 650을 통일, M04 종료). 이는 열린 길의 감쇠 누적 예산이며 벽을 관통하는 직선 반지름이 아니다. 화면 파동도 같은 값을 쓴다. 키가 큰 책장은 소리와 파동이 통과하지 않고 돌아간다.

## 4. 소리 전파와 공간

| 항목 | 현행 구조 |
|---|---|
| 공간 표현 | 기본 25cm 정사각 격자, 벽·바닥·간선 정보 |
| 소리 | 열린 연결과 바닥 감쇠 비용을 따라 확산 |
| 소리 크기별 기본 예산 | 大 500 / 中 250 / 小 190cm, 실제 DA 기준 |
| 전달 속도 | 공유 기본 600cm/s |
| 소리를 듣는 적 | 갑옷 |
| 촛불 | 청각 유인 대상 아님 |
| 시각 표시 | 계산된 거리장을 이용한 짧은 파동 |

| 연결 | 고양이 | 갑옷 | 소리·시야 |
|---|---|---|---|
| 열린 문·아치 | 통과 | 공간 폭이 허용하면 통과 | 전달·시야 통과 |
| 캣홀 | 작은 몸체로 통과 | 몸체 여유 공간에 의해 차단·우회 | 소리 전달. 시야는 실제 차폐 판정에 따름 |
| 닫힌 일반 문 | 직접 열지 못함 | 문 열기 행동 후 통과 | 닫힌 문은 차단 |
| 벽 | 불가 | 불가 | 차단 |
| 동상·퍼즐 철창 | 실제 충돌에 따름 | 동적 장애물로 경로 갱신 | 동적 격자 장애물 반영 |
| 일반 가구 | 실제 충돌·크기에 따름 | 장애물·여유 공간 검사 | 태그·시야 충돌 설정에 따름. 모든 가구가 소리를 막는 것은 아님 |

일반 문은 갑옷이 열고 다시 닫지 않는다. 퍼즐 철창의 하강·복원은 별도 규칙이다. 원문의 모든 이동·소리·시야가 하나의 방 그래프 간선만으로 처리된다는 설명은 구현과 다르다. 현재 이동·소리는 격자를 공유하고, 시야·포획·바구니 접근은 물리 광선/캡슐 검사도 사용한다.

청각 대상과 도달 시각은 **발음 시점의 갑옷 위치**로 예약한다. 전달 직전 다시 위치를 판정하는 구조는 아니다. 이동하는 갑옷이나 전파 도중 닫히는 장애물에 어떤 의미를 줄지는 M05의 명시 대상이다.

## 5. 갑옷

갑옷은 순찰하고, 소리의 발생 위치를 조사하며, 고양이를 감지하면 붙잡는다. 캣홀을 직접 통과하지 못하고 갑옷이 갈 수 있는 경로로 우회한다.

### 5.1 정보 우선순위와 상태

현재 승인 범위와 구현의 큰 우선순위는 **근처 감지·포획 > 소리 조사 > 표식 추적**이다. 최초 원문의 표식 최우선은 현행 규칙이 아니다. 방울과 발소리를 구분하여 “방울만 표식보다 우선”으로 바꾸는 안은 채택하지 않은 제안이다.

| 상태 | 목표·행동 | 종료·전환 |
|---|---|---|
| 순찰 | 배치된 순찰 지점, 걷기 | 소리·표식·근처 감지에 반응 |
| 소리 조사 | 소리 발생 당시의 고정 좌표로 이동 | 도착 후 돌아보기 |
| 돌아보기 | 조사 지점에서 주변을 살핌 | 새 소리, 근처 감지, 조사 종료 |
| 표식 추적 | 유효한 표식 고양이의 현재 위치 | 소리 조사로 중단 가능, 표식 해제/담당 교체 |
| 복귀 | 원래 자리·순찰 경로로 걷기 | 순찰 재개 |
| 문 열기·회전·포획 | 행동별 소유권과 중단 규칙 | 연출 완료 또는 안전한 취소·복구 |

| 새 소리가 올 때 | 수용 규칙 |
|---|---|
| 근처 감지·포획 중 | 새 소리로 대상 교체하지 않음 |
| 조사 이동 중 | 더 큰 소리만 조사 위치 갱신 |
| 돌아보기 중 | 크기와 무관하게 수용 |
| 순찰·복귀·표식 추적 | 소리 조사 수용. 실제 경로 계산이 가능해야 함 |

조사가 끝나도 표식이 남아 있으면 추적을 재개한다. 바구니 등으로 표식이 사라지면 과거 소리로 실제 위치를 계속 알아내지 않는다. 조사 좌표를 고양이의 현재 위치로 갱신하면 유인 규칙 위반이다.

반응 연출은 옛 표처럼 모든 순찰·복귀 소리에 항상 같은 지연을 주지 않는다. 현재는 발소리를 제외하고, 제자리 또는 첫 순찰 경고 조건에서 재생하며, 재탐색 대기만으로 첫 반응을 반복하지 않도록 되어 있다. 이 상태 설명은 코드에 맞춰 갱신했다.

### 5.2 감지·포획

좁은 원형 감지와 실제 시야 차폐·몸체 통과 검사를 함께 쓴다. 현재 공유 감지 범위 150cm에 고양이 판정 반경 15cm가 반영되어, 표시 경계는 고양이 중심 기준 약 165cm다. 포획은 철창·벽을 뚫고 성립해서는 안 된다. 표시가 보이는 것과 실제 포획이 가능한 것은 몸체 경로 차단 때문에 다를 수 있다.

**현재는 감지에 성공하고 몸체 통과 경로가 비어 있으면 즉시 포획 연출을 시작한다.** 원문의 ‘먼저 감지 추적 → 실제 접촉하면 포획’이라는 별도 추격 단계와 다르다. `StartCatch`에서 별도 접촉 거리 문턱을 검사하지 않는다. 따라서 이 원은 현재 포획 위험 구역으로 읽어야 한다. 해당 동작을 최종 규칙으로 유지할지 별도 감지 추격/접촉 포획으로 나눌지는 M11에서 사용자에게 확인한다.

한 번의 포획/시간초과/전환은 하나의 소유자만 진행한다. 다른 갑옷이 중복으로 잡지 않는다. 포획 중 타이머·카메라·입력·충돌 소유권을 정리한 뒤 재시작한다. 일반 디버그 감지·경로 표시와 사용자용 위험 표시는 구분한다.

## 6. 촛불과 표식

촛불은 소리를 따라 움직이지 않는 시각 감시자다. 고정형은 회전하고, 이동형은 배치 경로를 이동한다. 고양이를 발견해 표식을 남기며 직접 포획하지 않는다.

- 원뿔 시야와 벽 차폐를 검사한다. 발견 게이지 없이 표식을 적용한다.
- 발견 후 몸과 시야가 허용된 각도 안에서 고양이 방향을 향한다. 이는 위치를 따라 쫓아오는 갑옷 추적과 다르다.
- **현재 구현에는 원뿔 외의 접촉 거리 감지 45cm도 있다.** 벽은 관통하지 않는다. 바닥 원뿔만이 모든 감지 범위를 뜻하는 것과 충돌하므로 표현·규칙은 M03에서 결정한다.
- 표식은 고양이 몸 위 구체·빛으로 표시한다. 일반적으로 바구니 진입에서 해제한다.
- 승인된 Stage1 출구 복도 진입·재시작·맵 전환도 표식/적 추적을 정리하는 예외다. “바구니 이외에는 절대 해제되지 않음”으로 쓰지 않는다.

표식 담당은 현재 **1,500cm 내 가장 가까운 갑옷 1기**다. 벽·닫힌 문은 호출을 차단하지 않지만 이동 경로는 그대로 적용한다. 담당이 자주 바뀌지 않게 현재 거리의 0.8배보다 충분히 가까운 후보로 교체하며, 후보 갱신은 약 0.25초 간격이다. 실제 표식 경로 재탐색 기본 간격은 0.4초이며 고양이의 25cm 셀이 바뀌는지도 검사한다.

원문의 “최대 3기 호출”은 확장 후보이며 현행 완료 요건이 아니다. 별도 갑옷 간 정보 공유나 표식 중 살금살금 소음 페널티는 현행 필수 기능으로 채택하지 않았다.

## 7. 바구니와 캣홀

| 구분 | 바구니 | 캣홀 |
|---|---|---|
| 역할 | 은신·표식 해제 | 고양이 전용 작은 통로 |
| 진입 | F, 거리·방향·접근 경로·바닥 검사 | 실제 이동·충돌 |
| 표식 | 진입 단계부터 안전 판정, 표식 정리 | 해제하지 않음 |
| 방울 | 금지 | 주변 NoBellZone에서 금지 |
| 갑옷 | 은신 중 직접 포획하지 못함 | 통과 불가, 경로 우회 |
| 퇴장 | 출구 캡슐·지면·막힘 검사 | 일반 이동 |

2026-11-25 사용자 최종 수정 요청: 천 덮개형 은신함은 후면을 포함한 모든 접근면에서 진입할 수 있다. 은신 중 평소 보행과 동일한 쿼터뷰 WASD 입력으로 탈출 방향을 지정하고 F로 확정한다. 카메라의 수평 전방·우측 벡터를 그대로 사용하며 바구니 방향으로 스냅하지 않는다. 대각선 조합도 평소 이동과 같다. 현재 선택한 위치 하나만 기존 점선 경로와 원형 안내로 표시한다. 키를 놓으면 마지막으로 직접 선택한 방향을 유지하며, 막혀도 다른 출구를 자동 선택하지 않는다. 천 클립은 실제 이동 방향을 따라 선택하며 고양이 방향을 결정하지 않는다. 사용 중인 바구니의 선택 방향만 0.2초 간격으로 검사하고 방향 변경·F 확정·착지 시 즉시 검사한다. 전체 출구 목록 검사와 A/D 순환은 사용하지 않는다. 바닥 지지·실제 캡슐 경로·복원 충돌 프로필을 유지하며, 실패나 중단 시 이동·충돌·애니메이션·점유 상태를 안전하게 복구한다.

현재 은신 완료 후 고양이 메시를 숨긴다. 원문의 **바구니 안 실루엣 표시는 미구현/채택 재확인 항목**이다. 별도 적의 바구니 수색·꺼내기 행동도 없다. 기다릴 수는 있지만 스테이지 1·2의 남은 시간은 줄어든다.

캣홀은 통과 목적의 경로이며 왕복을 허용한다. 체류 제한 시간이나 강제 이동을 별도로 구현했다는 증거는 없다. “머무를 수 없음”을 시스템 보장으로 적지 않는다. 체류/왕복의 허용 범위는 M06에서 결정한다.

## 8. 시간과 실패

**현행은 스테이지별 남은 시간 시스템이다.** 게임 전체 하나의 증가형 각성 게이지·마왕 단계별 적 강화·숫자 타이머 금지는 현재 기획에서 제외한다. 마왕이 깨어난다는 실패 서사는 유지한다.

| 구간 | 임시 배분 | 규칙 |
|---|---:|---|
| 튜토리얼 | 제한 없음 | 다음 구역의 시간 제한을 설명, 시간초과 실패 없음 |
| 스테이지 1 | 600초 | 실제 조작 가능 상태에서 감소 |
| 스테이지 2 | 900초 | 실제 조작 가능 상태에서 감소 |
| 경고 | 남은 비율 30% / 긴급 15% | 편집 가능한 초기값 |

600/900초는 동선 측정을 끝낸 최종 밸런스가 아니다. 이동·대기·유인·스태미나 회복 시간을 포함해 확정한다.

| 상황 | 시간 |
|---|---|
| 시작/도착 시네마틱·로딩 | 정지, 조작 복구 후 시작 |
| 설정·월드 일시정지 | 정지 |
| 퍼즐 문 연출·포획·실패 처리·전환 | 정지 |
| 일반 방울 동작·바구니 은신·관찰·회복 대기 | 감소 |
| 퍼즐 완료·자동 저장 | 시간을 채우지 않음 |
| 이어하기 | 저장한 남은 시간 유지 |
| 포획/시간초과 재시작 | 해당 스테이지 배분을 다시 채움, 완료 퍼즐 유지 |
| 명시적 스테이지 처음부터 재시작 | 해당 스테이지 진행 초기화·시간 재충전 |

0초가 되면 `마왕이 깨어났다` 안내와 기존 실패·페이드·재시작 흐름을 사용한다. 포획·출구와 경쟁해 두 번 재시작하지 않는다. 기존 최대 각성 유지→즉시 재실패 모순은 이 새 규칙에서는 적용되지 않는다.

완료 퍼즐을 유지하고 실패 때 시간을 채우므로, 여러 시도에 걸쳐 퍼즐을 하나씩 완료하는 플레이가 가능하다. 이는 최신 요구의 결과다. 한 번에 탈출하는 긴장감을 얼마나 요구할지는 M02에서 논의하되 저장/재시작 규칙을 임의로 되돌리지 않는다.

스테이지 2 출구는 기존 레벨 흐름을 통해 스테이지 3으로 연결된다. 출구의 안전 복도에서 추격이 끊기고, 창고의 승강기에 타서 F로 고리를 당기면 상승 시네마틱 뒤 스테이지 3 입구에 도착한다. 승강기는 도착 후에도 남지만 다시 작동하지 않는다([승강기 전환](ElevatorTransition_Delivery.md)). 스테이지 3의 최종 대문·출구는 완료 화면으로 연결되며 전용 엔딩 시네마틱은 남아 있다. 전환 검증은 [최종 통합 검사](../Reviews/Stage3Integration_2026-11-25.md)의 자동화 범위이며 적을 회피하는 수동 연속 완주와 구분한다. B 퍼즐까지 반드시 완료해야 하는지는 M07의 결정 대상이며 현재 Stage2 출구 코드에는 A/B/C 전체 완료 검사가 없다.

## 10. 스테이지 2 동상 퍼즐

동상 뒤에서 이동 입력으로 축 방향으로 민다. 별도 전용 밀기 버튼·끌어당기기·대각선 밀기는 제공하지 않는다. 벽·다른 물체·캐릭터·지면을 검사하며, 역방향에서 다시 밀 수 없는 막힘을 줄이도록 접근 공간을 검사한다.

| 퍼즐 | 연결 문 | 역할 |
|---|---|---|
| A | Gate02 | 미로 진입 연결 |
| B | Gate05 | 후속 방 아래 통로 연결 |
| C | Gate11 | 시작 연습 구간 연결 |

약 80% 평면 접촉과 높이·소켓 축 허용 조건을 만족하면 정확한 위치로 안착한다. 동상 눈·발판 변화 후 카메라가 문으로 이동하고, 문이 바닥 아래로 내려간 뒤 카메라·입력을 복구한다. 최소 하강 거리 280cm, 기본 속도 140cm/s, 발판 이동 2cm이며 최종 판정은 실제 메시 높이와 바닥 여유도 반영한다.

완료된 동상은 영구 완료로 저장한다. 동상이 발판에서 떨어지면 자동으로 문이 닫힌다는 초기 문서는 현행 규칙이 아니다. 문 하강 완료 이후 A/B/C 해당 비트를 기록하고, 이미 완료된 링크는 다시 완료 이벤트/보상을 발생시키지 않는다.

2026-11-23 요청으로 동상 되돌리기 UI·일반 상호작용 경로는 제거했다. 현재 맵에는 복구 받침대 액터도 없다. `CatrunPuzzleReset`과 테스트용 복구 API가 코드에 남아 있는 것은 플레이어에게 복구 버튼이 제공된다는 뜻이 아니다. 최신 스테이지 리셋은 설정의 확인 절차를 사용한다.

복원 시 완료 동상·발판·문을 최종 위치로 조용히 복구하고 연출·완료 보상·재저장을 반복하지 않는다. 아직 덜 민 동상 위치·일반 문 개폐·적 상태는 저장하지 않는다. 저장/복원 위치의 실행 검증 상태는 감사 보고서를 따른다.

## 11. 저장·이어하기·재시작

기존 진행 관리자와 저장 작성자를 확장한다. 임의 액터 전체 스냅샷이나 중복 진행 관리자를 만들지 않는다.

| 저장 대상 | 처리 |
|---|---|
| 마지막 구간·최고 해금 | 유지, 새 게임/리셋으로 최고 해금을 낮추지 않음 |
| 튜토리얼 안내 완료 | 보존 |
| Stage2 A/B/C 완료 | 명시적 비트 마스크 |
| Stage1/2 남은 시간 | 밀리초 단위 정수 필드 |
| 고양이 구간 내 좌표 | 저장하지 않음. 이어하기/실패 모두 일반 시작점 |
| 미완료 동상·적·표식·일반 문 | 재로드 때 새 상태 |

저장 스키마는 v4 확장이며 기존 v1~3을 읽는다. 손상·미지원·일시 읽기 실패를 “저장 없음”으로 취급해 덮어쓰지 않는다. 기존 Windows 원자 저장·잠금·해금 병합을 유지한다. 완료 저장/시간 저장/실패 시간 재충전/명시적 리셋은 순서를 구분하여 늦은 저장 콜백이 초기화한 진행을 되살리지 않게 한다.

메뉴 복귀·정상 종료 시 남은 시간을 반영한다. 현재 코드에는 정기적인 시간 자동 저장 간격이 없다. 비정상 종료 때 마지막 저장 이후의 시간 감소가 되돌아갈 수 있으며 허용 손실 범위는 M08에서 정한다. 정상 종료의 실제 프로세스 간 지속성은 별도 수용 검사를 통과해야 한다.

설정의 `스테이지 처음부터 다시 시작`은 확인 후 **현재 구간** 진행·시간만 초기화하고 다른 구간 진행·최고 해금·안내 완료를 유지한다. 이전 C/Gate11 체크포인트로 고양이를 옮기는 규칙은 최신 요구에서 폐기했다. 직접 에디터 플레이는 사용자 실제 진행 슬롯에 쓰지 않는다.

## 12. 화면·UI·연출

- 단층 중심의 고정 각도 카메라. 튜토리얼 원래 구도 유지, 기본 카메라 배율 Tutorial 1.0 / Stage1 1.15 / Stage2 1.30.
- 벽·책장 등 가림은 기존 환경의 모습과 조명을 보존하며 고양이를 읽을 수 있게 처리한다. 가림용 메시가 이동/소리 충돌을 추가하면 안 된다.
- 촛불 시야·갑옷 감지·표식·실제 소리 파동으로 위험의 이유를 전달한다. 시야 밖 접촉 감지의 별도 표현은 아직 결정이 필요하다.
- 미니맵은 우상단에 유지하며 Tab을 누르는 동안 확대하고 놓으면 복귀한다. 고양이 초록, 적 빨강. 출구·열린/닫힌 문·캣홀은 모양으로도 구분한다.
- 미니맵 배경은 저채도 차콜/웜그레이를 기준으로 가독성을 우선한다. 매 프레임 전체 액터 탐색·배경 렌더링 대신 등록 캐시와 이벤트·주기 갱신을 쓴다.
- 스태미나·방울 아이콘/진행/초·남은 시간은 BP/UMG에서 편집 가능하게 한다. 계산은 실제 게임 상태를 읽고 입력 포커스를 빼앗지 않는다.
- 메뉴·시네마틱·암전·설정 중 플레이 HUD를 숨기고, 종료 뒤 복구한다. 제목/기존 튜토리얼 안내를 침범하지 않는다.
- 스테이지 2 출구의 복도·창고·승강기에서는 F 이전에도 미니맵을 숨기고, 구간을 벗어나거나 스테이지 3 도착 연출이 끝나면 복구한다. 승강기에 들어가면 승강기 밖 주변을 암흑으로 가린다.
- 새 게임은 원래 인트로, 이어하기·실패·수동 재시작은 해당 재시작 정책에 따라 연출을 생략한다. Stage1 포털 출발과 Stage2 도착 연출의 완료/취소/소유권을 구분한다.

최신 HUD 에셋 작성 완료와 새 프로세스 로드를 확인했다. 실제 화면·입력 통합 수용은 병행 작업 중이다. 클래스·텍스처 존재만으로 최종 UI 품질 완료를 선언하지 않는다.

## 13. 아트와 오디오

기존 고양이 외형·얼굴·비율·리그·애니메이션 정체성을 유지한다. 갑옷·촛불·환경 교체는 기존 판정 캡슐·문 폭·캣홀 치수·경로·표식 규칙과 구분한다. Stage2 적 외형, 바구니 변형, Stage3 환경 아트는 각각의 제작 작업과 연동하되 에셋 준비를 게임 구간 구현 완료로 계산하지 않는다.

게임플레이 소리 이벤트와 실제 청각용 음원은 별개다. 방울·발소리 전파가 작동해도 완성된 BGM/SFX가 전부 연결됐다는 뜻은 아니다. 현재 오디오 훅과 일부 SoundWave는 있으나 최종 음원 제작·배치·믹싱·전체 재생 수용이 남아 있다. 이 문서는 음원 생성·유료 사용을 승인하지 않는다.

## 14. 구현 구조와 알고리즘

| 기능 | 현행 책임·구현 |
|---|---|
| 소리 공간 | `CatrunGridData`, 바닥·간선·비용·동적 퍼즐 장애물 |
| 갑옷 길찾기 | 방향 상태와 회전 비용을 포함한 격자 A* |
| 소리 확산 | 우선순위 힙 + Eikonal 근사 갱신. 단순 방 그래프 다익스트라로만 설명하지 않음 |
| 시야·포획 | 광선/원형 감지·실제 몸체 경로 검사 |
| 바구니 선택 | 거리 후보 + 접근면·캡슐·바닥 검사. 최근접 바구니 BFS 아님 |
| 표식 | 월드 표식 관리자, 담당 갑옷 1기 선택 |
| 진행·시간·저장 | 기존 LevelFlow/FlowSession/ProgressWriter/AtomicSaveGame |
| 스태미나 | 고양이의 SprintComponent |
| 방울 | 기존 행동 승인 시각·네이티브 상태 조회·실제 소리 이벤트 |
| 퍼즐 | C++ 밀기/안착/문/저장, BP가 연출 조립 |
| UI | C++ 상태·입력 정책, BP/UMG 외형·배치 |

원문의 최근접 캣홀·바구니 BFS는 확인되지 않았다. 플레이어가 실제 사용하는 길안내 요구를 확정하기 전에는 필수 미구현 버그로 취급하지 않는다. 클래스/속성명 문자열로 BP 상태를 읽는 연결은 일부 남아 있어 변경 시 회귀 검사가 필요하다.

## 16. 완료 판정과 플레이 검증

1. 새 게임 → 튜토리얼 학습 → Stage1 → Stage2 출구를 무적·순간이동·강제 완료 없이 연속 통과한다.
2. 각 스테이지의 방울 사용 경로와 무방울 경로를 비교하고 유인 필요성을 기록한다.
3. 소리는 원래 위치, 표식은 실제 위치를 목표로 하는지 상태·좌표를 기록한다.
4. 캣홀의 양방향 통과/갑옷 차단/방울 금지, 바구니 앞·뒤·막힌 출구·중단을 검사한다.
5. 스태미나 실제 소모/회복/고갈/벽·강제 이동 예외, 달리기 발소리 크기·간격을 검사한다.
6. A/B/C를 실제 밀기로 해결한 뒤 저장 → 포획/시간초과 → 일반 시작점 → 완료 상태 복원을 검사한다.
7. 새 프로세스 이어하기, 현재 구간 초기화, 타 구간 진행·해금 보존, 손상 저장 보존을 검사한다.
8. 제한시간의 시작·일시정지·일반 대기 감소·시간초과·포획/출구 동시 발생을 검사한다.
9. 미니맵 좌표/열림 상태/Tab 유지, 상태 HUD·제목·옵션·시네마틱 간 겹침과 포커스를 검사한다.
10. 패키징한 Windows 실행 파일에서 시작·전환·저장·음향·성능을 확인한다. NullRHI 테스트는 화면·GPU·음향 검증을 대신하지 않는다.

자동화 통과, 에셋 로드, 국소 런타임, 수동 전체 완주는 각각 별도 증거로 기록한다. 감사 실패나 모호한 기획을 문서 수정만으로 해결했다고 처리하지 않는다.
